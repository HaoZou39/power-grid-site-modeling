# PILOT 选线机制迁移规格

## 授权与边界

用户已确认按本规格逐轮迁移 PILOT_v2 的第一类搜索机制：先保留原函数与 Python/NumPy 控制流，再接入当前模型，不先张量化。用户此次明确允许复制选定原始源码，作为 AGENTS.md 中独立重写原则在本任务中的例外；不修改用户已有 AGENTS.md 变更。

源码对照固定到 PILOT_v2 提交 `4e9d2c859ff9e1f4caed9a76ad14f08f66d4b3e0`。`tests/reference/pilot_v2/` 只存只读原文件、来源与内容哈希，不是生产依赖。原代码不运行旧地图加载、绘图、偏好或模型接口。函数级夹具只执行选定函数，注入确定的评价、几何与随机输入；不能将它当作旧软件全流程复现。

当前四目标、工程约束与原 CPU 精确复核不变。允许适配评价接口、塔基/档段检查、坐标单位和必要预算；每项偏离原函数的变化必须记录。初版保留原算子内部接受顺序，放开非支配折中候选另立实验。旧目标下标按语义映射，禁止沿用旧地类价格、安全评分、定长整数编码与固定塔数范围。

## 接入契约

沿用 `routing.nsga2`、Jobs、CLI、独立快照与线路产物。增加 `algorithm.search_strategy=standard|pilot_reference`，迁移期默认 standard。迁移参考策略首版只接受 NumPy、CPU、reference/compiled_cpu 评价，不兼容组合明确报错。页面显式选择策略，历史保留完整配置。

新策略开关及研究参数分组维护，默认数值只写在 `config/default_config.json`，dataclass 只定义字段与类型。原源码快照中的历史常量仅用于对照，不成为第二份生产默认。新模块不读取旧仓库和原始场景文件。

接入轮类型为 `PilotRoutingConfig`：`enabled_mechanisms` 与初始化、局部、全局预算倍数；该分组置于 `RoutingConfig.pilot`。只接受当前已实现的机制，不提前接受尚未迁入的开关。所有增强关闭时复用标准 CPU 搜索，阶段限额不改变基线轨迹；机制开启后再激活对应限额。共享 `EvaluationBudget` 维护记录、完成时间与分类计数，每次调用的窗口额度独立，总额度共用。生产适配器只有固定源码来源元数据，不依赖测试快照文件。

内部可使用包含固定端点的列表，边界统一转换为 `Route`。节点检查完整塔基，边检查当前档距/转角/间距与人工禁跨；道路、水体等允许跨越。所有完整评价请求（含重复或缓存命中）走同一预算入口；完全相同且已携带评价的候选可直接复用，另记复用次数。节点/边检查另计。最终独立复核与输出重建另计，不混入搜索预算。

初始化、局部和全局调用分别有阶段上限，且不超过总剩余额度。截断只保留完整评价状态；局部额度分给选中精英，避免一个精英吞掉全部额度。新增摘要记录阶段计数、实际代数、来源及哈希；引入内部搜索后不再用旧代数公式解释预算。

参数初值按原概率/尝试/周期/比例；长度按已确认米制适配，RRT 最大扩展长对应最大档距，最小/最大比例保持原版；树预算按松弛档数增长。A* 使用当前导航步长的 1/2/3 倍。新增合法种子参与初始塔数上限估计。所有具体初值进入唯一 JSON，校准独立记录。

### RRT 轮的具体适配

`pilot.enabled_mechanisms=["rrt"]` 是本轮唯一新开关，standard 策略不得携带启用机制。RRT 参数包括目标偏置、最小扩展/最大档距比例、每个松弛档的树迭代数、种子数下/上限及种群除数、树尝试倍数/最少次数和自由目标采样次数，数值只在默认 JSON。最大扩展为当前最大水平档距，树迭代上限为参数乘以直线松弛档数；目标数和尝试上限沿用原 `_build_astar_rrt_population` 公式。

生产函数保留原 `_rrt_path` 的目标偏置抽样、全树最近节点、均匀扩展、节点/父索引、近目标连接及父链回溯顺序。坐标适配明确移除旧粗栅格取整/解码，使用连续米坐标与固定接入点；自由目标以相同的有界拒绝采样在场景内均匀抽取，采样耗尽返回无目标，不偷偷选原点。边改为当前完整前缀延伸检查，允许跨越不能落塔的地物。原函数的 A* 回退不放进 RRT 成功计数：本轮树失败只返回空，现有参考线/A* 仍独立保留。为维持本轮边界，不迁移旧定长编码、随机固定塔数重采样与多尺度 A*。

扩展恰好到达终点时直接按固定接入点连接，不把终点当作新增塔检查。旧半个粗格的最小移动检查改为排除数值重合；工程最小塔距由当前 2r 检查统一控制，固定端点继续豁免，不引入额外的粗格尺度约束。旧保存任务中缺少的新增 PILOT 参数由插件层从当前默认 JSON 补齐；项目默认 JSON 本身仍须完整，不接受缺字段。页面提供 RRT 实验复选框，切回 standard 时显式清空机制列表；历史保留所选开关。

先生成当前参考线，再尝试加入精确去重的 RRT 种子；所有完整评价共享初始化窗口，启用机制时其上限为初始化倍数乘种群数，再受总预算限制。只有完整评价可行的新种子参与初始塔数上界估计，不修剪/重新采样 RRT 路径。记录树尝试、实际扩展迭代、树成功、可行/唯一种子、节点/边检查和阶段耗费。受控随机输入对照原函数扩展与回溯；角色诊断记录初始可行唯一线路的形状多样性，不作为迁移期间的质量门槛。

## 初始化衔接诊断

用户在 RRT 负结果分析后明确同意优先处理冗余塔位、初代比例和上界耦合，并快速验证。本次先做初始化闭环的累计消融，不推进其他 PILOT 算子。`pilot.initialization_mode` 提供 `legacy`、`pruned`、`balanced`、`bounded` 四个显式模式，旧任务缺少该字段时解析为 legacy。默认策略仍为 standard，RRT 默认关闭。

- legacy 保留已验证的原始接入轨迹。
- pruned 对每条可行 RRT 种子复用 `prune_reference`，每次删除完整评价且其余三个目标不恶化；仅最终路线作为初代候选，内部试探仍计预算并保存在搜索档案。塔数上界只由最终塔位估计。
- balanced 在 pruned 上补齐初代至种群目标规模，RRT 来源槽位不超过种群数量除以现有 RRT 种群除数，其余由原参考路线及其后代构成。填充复用当前结构变异、修复与完整评价，优先不同且可行的后代。达到初始化预算上限仍不足时，仅复制已有完整评价状态补齐，并显式记录唯一数量、复用槽位和预算耗尽，复制不算新评价。初始化记录来源和完整数量，不能以种群目标冒充实际不同候选数。
- bounded 在 balanced 上将周期性上界探测锚定到加入 RRT 之前的参考上界。现有可行种子的塔数仍允许保留；活动上界为已保留种子上界与锚点扩展结果的最大值，避免把原始 RRT 节点数作为后续每次扩展的额外起点。它不强行删改已有合法种子。

预处理和填充均受同一初始化窗口及总评价预算约束，为填充预留所需槽位的评价额度。初始化预算倍数继续来自唯一 JSON，调整上限用于容纳完整预处理和初代补齐，不增加总评价次数。原始模式必须通过冻结任务的逐候选等价检查。

快速验证先使用独立校准 seed 131–133、8192 次、种群 64；先筛楠溪江 200 m，再扩展三工况。旧校准外的 seed 123–127 和 32768 次用于随后确认，不能把三 seed 快速筛查表述为正式收益门槛通过。所有组使用相同预算、模型、输入和共同报告参考；记录实际初代大小、来源比例、删除次数和上界锚点。每次累计修改均先做小型确定性验证，再进行真实对照；无收益的阶段保留清楚的诊断结论。

若衔接调整仍不足，允许在上述校准 seed 上分别检查现有 `rrt_goal_bias` 与 `rrt_min_step_ratio` 的米制适配，固定其他配置；不增加工程成本权重。参数取值和对照组在运行前写入实验 manifest。此前已查看的确认 seed 不反复用于调参，校准完成后另用未参与选择的新 seed 做复验；不能据单个 seed 切换默认。

## 固定实验与验证

真实工况由三份已保存任务冻结：苍南 `routing-1793062433810`（220 m/10 m/90°），楠溪江 `routing-1793062752732`（100 m/10 m/100°）和 `routing-1793062828655`（200 m/10 m/100°）。原起终点、道路参数和输入哈希不得改变。同场景的不同工况使用独立实验标识。

正式对照使用上述已保存实验的独立输入快照构建隔离场景根，原始场景允许用户继续编辑。若运行期间实时场景变化，必须分别核验只读快照和候选哈希；可明确生成恢复报告，但不得将实时源文件宣称为未变化。初始几何多样性只统计预算内、初始塔数范围内的可行且精确去重的初始化候选，报告使用固定弧长采样。

迁移阶段使用三份冻结工况、固定单 seed 和既定小预算做正确性接入，所有标记可行的候选经原 CPU 复核；不进行多 seed 收益筛选或参数校准。P9 完成后冻结代码和参数，P10 使用预先固定的五个未用于校准的 seed、相同完整评价预算，对照标准 CPU、标准张量和完整迁移版本，再做初始化、交叉变异、局部、全局四组移除消融。至少一个 seed 重复两次检查复现。共同前沿与 min/range 只用于报告；报告 IGD+、epsilon、覆盖、四目标分布、首次可行、实际代数、耗时和内存，不宣称真实集合是全局最优。

## 模块化后续迁实施契约

### 已确认适配

采用独立 PILOT CPU 驱动，共享现有评价、账本、NSGA-II 数学与最终归档；不将迁移专用控制流写入标准 NumPy/张量驱动。新驱动依次执行父代选择、邻近交叉、独立变异、环境选择、周期精英局部搜索、每代全局注入和存活计数更新。局部触发采用 `(generation - 1) % interval == 0`；全局搜索在有受支配个体时每代尝试，停滞计数只决定优先替换对象。

A* 代价及启发采用 DEM 端点高程组成的三维距离，不用旧地类价格；尺度取当前导航步长的原有尺度倍数。节点必须能放完整塔基，档段沿用当前可跨地物规则，固定端点豁免新增塔基条件。无路径显式返回空，不把直线算作 A* 成功。

长度换算系数为当前最大档距除以冻结原 RRT 最大扩展长度。长度常量按该系数换算，原自适应半径满足 `r_m(d_m) = s * r_old(d_m/s)`。概率、次数、角度和无量纲比例保留原值；所有生产初值只在默认 JSON。距离提示采用当前禁落塔数据，不能作为新的安全目标或代替完整合法性检查。

混合初始化新增 hybrid 模式，保留旧四种模式。路径保留原二维弧长重采样顺序，目标塔数从当前动态范围抽取，端点精确保留。只在初始化时用完整可行的处理后种子扩大初始上界，其他阶段不擅自改范围。种子、内部试探、入选和复用槽位分别记录；不足时仅复用完整评价状态。

候选比较保留无偏好分支的决策顺序与目标专项接受分支。可行性和总违例用当前定义；原长度目标映射到当前三维长度，原平滑目标映射到水平曲折度，旧安全评分不迁入。已在本次调用中评价的返回候选复用其账本身份；返回旧父代且没有本次新评价时，提交一次子代评价以保证预算推进。只复制填充槽位不算评价。

### P1 运行与配置实现

`pilot.core` 集中维护新 CPU 组件参数；旧任务缺少该段或段内新增字段时由任务解析从唯一 JSON 补齐，项目配置本身仍严格完整。`cpu_driver` 是独立入口的显式机制开关，当前骨架委托旧 CPU 驱动；几何与预算状态在每次初始化创建，不进入任务 JSON。原有参数值与所有关闭机制轨迹保持。正确性验证入口 `experiments/validate_pilot_components.py` 显式设置不计算质量指标，真实 Jobs 使用隔离应用及输出。

### P2 A* 邻接适配

保留原 heap、visited、代价松弛和回溯顺序。生产节点用粗格中心与固定端点，不用整粗格任一禁像元就封格；节点检查完整塔基。沿原八个方向允许连接当前最大档距内的合法节点，可跳过不能落塔的中间节点，连线仍检查人工禁跨区；这是允许跨越地物的几何适配，不改变工程约束。原单格八邻接内核仍用受控函数对照。三维端点距离作为边代价和启发，无路径不计成功。尺度逐个搜索，缓存只属于本次运行；最终种子复用既有带预算删塔并完整评价。

### P3 混合种群适配

新增 hybrid 初始化模式，先复用当前参考生成来确定动态范围与完整评价后备，再按原 A*、RRT、随机目标塔数/基线路径填充的顺序建立种群。重采样保留原二维弧长插值；只投影新增塔，端点不取整，超档距复用现有有限修复。完整不可行但在范围内的候选仍可进入约束优先种群，不伪装为可行；只有完整可行种子可扩大初始化上界。去重基于连续坐标精确身份。原无限最终填充改为复用已评价状态，记录槽位与唯一数，避免预算外评价。新 A* 路径缓存绑定一次运行，后续全局填充可复用；不按场景 shape 共用缓存。

### P4 独立演化与交叉编码

新算子开启后独立 CPU 循环按原顺序执行；仅 cpu_driver/astar/rrt 的旧阶段仍委托原 CPU 循环以保留已验证轨迹。父代重选保留“不同索引”与有限重试含义，不改成强制不同坐标。交叉保留最近点排序、双向候选、首次改进后退出和无偏好接受。末尾保留原 sanitize→按父代塔数提示重采样→检查失败时按自然塔数再采样的控制流；塔数裁剪使用活动动态范围，取代旧 MIN/MAX 和定长编码。既有范围扩展的首个边界探查显式覆盖目标塔数。预算耗尽时仅返回已完整评价状态，不返回未评价编码结果。

### P5 独立变异与多试探

`path_mutation` 一次接入原独立触发、自适应半径和多次极坐标试探，避免人为拆出原代码没有的两套变异。交叉和变异概率独立抽取，原试探均围绕最初选中的一个塔位生成，不把接受后的坐标作为下一次随机游走起点。试探数、距离比例及投影净距偏置保持原值；偏置仅用于几何候选排序，不是旧安全目标。预算截断时返回最后一个完整评价状态。默认关闭；关闭该机制不额外消耗其随机抽样。

### P6 逐路径改进算子

shorten/smooth 显式开启原可选子代后处理支路，顺序为删塔后平滑；默认机制列表仍为空，原冻结 OFFSPRING_EMBEDDED_LOCAL_SEARCH=False 没有被静默改成默认开启。删除保留原“每个候选从原路径删一个点、不是接受后连续贪心删除”的顺序，长度专项目标映射到当前三维长度。平滑优先最大水平转角，目标映射到当前水平曲折度。VNS 先做函数级迁移，P7 进入精英调度后才开放该主循环机制。原半径推导的试探次数使用换算前单位半径，不能把米数当次数。原独立但未被参考主循环调用的 local_mutation 辅助函数不重复复制，实际高斯邻域由 VNS 迁移。

### P7 周期精英调度

`elite_local_search` 在环境选择后按原周期触发。只从可行非支配前沿选择各目标极值，随后按拥挤度补充稀疏精英；边界和稀疏精英使用 exhaustive VNS。其余前沿是否参与由唯一配置控制，保持原初值。每次局部调用上限为局部倍数乘种群数，剩余额度按尚未处理精英分配，每人保留一次编码后完整评价；完全相同的已评价候选复用身份。原始改善和重采样后改善分别记录，只有后者并入环境选择。预算截断不留下未评价子代。

### P8 全局注入、存活与去重

global_injection 每代在局部之后运行，有受支配个体且有预算才尝试；随机/RRT 填充占目标新候选的一半，其余从非支配前沿（不足时可行/全部种群）用私有 NumPy 流无放回选父代，沿用同一个子代流水线。全局填充不直接注入 A* 锚点，但保留原最小尺度 A* 作为填充基线；缓存仍限本次运行。新候选全程受全局窗口约束，禁止改塔数上界。只有达到连续存活阈值的受支配个体可优先移除，极值/前沿不因停滞直接删除。

连续存活按精确连续塔位身份计数，重复槽位只加一次，消失后重现从一开始。population_dedup 在公共环境选择前按相同身份保留可行性/违例更好的代表，中性并列保留原先索引；唯一数不足目标种群时按原版回退到完整池。全局来源累加在独立摘要中，不能覆盖初始化来源；真实新存活身份与复制提交分别记录。

## 完整 PILOT 的张量化加速

### 本轮已确认契约

用户已确认优先有效 GPU 批处理：保留单条线路内部的试探、接受和阶段顺序；不同线路并行，按固定批次顺序提交共享评价预算。固定提案用于 CPU/张量算子对照，GPU 自身相同配置和 seed 可复现；不要求 CPU 与 GPU 的同 seed 全部轨迹相同。新张量实现作为同一 PILOT 策略的可选执行后端，CPU 版本保持独立可用。标准策略与其既有张量后端不承载 PILOT 专用逻辑。

本轮只改变执行：四目标、硬约束、概率、试探数、阶段顺序、塔数扩展和评价额度规则保持。VNS 的编码后检查、原重采样和修复也保留；编码损失的质量优化另立实验。先以相同种群和预算验证正确性及速度，再扩展容量与质量实验。实际完整评价的总量与阶段量必须准确；几何预筛和取消检查另计。先生成几何合法请求，再按固定序号及剩余额度截断，禁止把预算外已计算的四目标静默排除账本。阶段公平配额继续作用于每个精英。

沿用已有 float64 TowerBatch `[B,K,2]` 与有效数量。端点独立，补齐位不参与几何或身份；容量跟随动态上界。随机提案按逻辑批次生成，与评价微批次区分，改变工作分块不改变同后端的提案、接受、结果和预算。精确去重比较有效连续坐标和塔数，不能量化；哈希碰撞必须核验。搜索阶段避免每条线路往返 NumPy/设备，CPU 档案按块保存完成候选，报告与最终原 CPU 复核仍在既有层完成。

几何复用 `modeling/routing` 的既有张量内核；新增批量查询和候选增量评价仍属于建模层，不复制四目标公式到算法。近阈值和人工多边形按当前精确契约复核，记录真实 CPU/GPU 分工。候选接受、rank、拥挤度与非支配选择均需受控提案对照，不能只看目标近似相等而忽略接受分支变化。

资源使用已有 devices、evaluation_batch_size、gpu_memory_budget_mib 和 context_cache_mib；必要的新工作配置先记录含义，数值只进默认 JSON。显存账目覆盖场景常驻、净距场、路径、试探展开、塔间距离、排序和档案传输；按路径/试探/塔位/线段分块，不生成种群乘整幅地图数组。双卡同步分担评价后恢复请求顺序并全局选择，后续单独验收。OOM 必须清楚报错并释放设备资源，不能静默缩小种群、预算或精度。

每阶段先实现受控小测试，再三冻结工况核对，完成必要文档与实验记录后本地提交，不 push。旧阶段 P0–P10 的有效输出不覆盖。复杂优先队列、人工几何或最终复核可以保留明确 CPU 边界；不能只把数组搬上 GPU 就宣称完整加速。现有标准策略的性能/数值门槛继续适用，正式计时先核对设备占用，不把带 profiler 或其他 GPU 任务争用的时间当作干净速度基准。

T2 的路径处理复用同一 TowerBatch：投影保留原逐方环、距离/净距字典序与首次成功环；净距仍为既有提示并保留 float32 EDT 的数值，不增加目标。变长去重保留固定端点，二维弧长重采样保持原插值口径；不因塔数相同就跳过重采样。固定端点只在明确的路径边界插入，不作为可移动塔。坐标处理与后续有限修复分开验证，临时容量可容纳原修复插入的塔，不能悄悄截断有效塔位。

T2c 有限修复保留原规则：只在最长水平档超限时插入中点，然后对该条线路执行原塔位修复；不额外修复本来没有触发插塔的线路。塔位随机试探之间互相独立，可跨点/线路并行，但每点只取原顺序第一个合法试探；始终围绕该次修复前的原点生成，不做随机游走。GPU 逻辑随机表与工作分块分离，受控测试可显式注入标准正态提案。容量预留原 repair_attempts 允许插入的数量，未成功修复仍返回真实候选，由后续统一评价判定，不能伪装可行或截掉超出范围的实际塔。

受控塔位修复正态表为 `[R,B,K,2]`，档距循环可提供 `[R,R,B,K+R,2]`，其中 R 来自 repair_attempts、K 为本次输入容量；类型/设备必须与路径一致。正式执行逐次生成逻辑提案，不常驻整个外层多轮随机表。

T3 的设备候选携带 TowerBatch、TensorEvaluationBatch 和完整评价序号，排序继续复用公共张量 NSGA-II。父代二元锦标赛保留无放回的两个竞争索引、不可行 CV 容差与可行 rank/拥挤度/随机平局，另做有限不同父代重选。GPU 平局按固定输入候选序号稳定处理，不要求复制 NumPy 历史前沿展开顺序。精确身份使用有效 float64 坐标的整数位型与塔数，补齐位不参与；不量化，不存在只凭哈希合并的碰撞风险。重复代表保留原可行性/CV 容差逐次比较，唯一数量不足时回退原池；连续存活只保留上一代身份，重复槽位不叠加计数。
