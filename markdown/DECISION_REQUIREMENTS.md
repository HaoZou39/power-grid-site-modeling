## 已经做到

- 用地图是场景里的 `landuse_1m.npy`。类别为 `0` 其他、`1` 农田、`2` 建筑、`3` 道路、`4` 山体自然、`5` 水体。
- 地图按农田、建筑、道路、水体着色。图例开关只影响显示。
- 农田可以保持不可建设，或改成允许建设并按系数计入现有 obstacle 软约束。建筑、道路、水体仍是硬禁止。
- 禁区和可行域下面都可以选画圈或方框。画圈松手后自动闭合。方框用两次点击确定对角线，取轴对齐外接矩形。这些范围在本次优化前栅格化。有可行域时搜索限制在这些圈的并集内。场景里的原始用地图不被改写。
- 站址矩形内的高程方差和平整度已经进入目标。到最近道路的距离已经进入目标。足迹最大坡度、沿道路运输成本和进站坡度已经可以报告；它们不改变可行性，也不进入这三个目标。
- 点击同类连通区域会生成一块禁区。点击分割模型只有占位接口，调用时明确报错。
- 按中心经纬度新建场景时，数据阶段会调用 `masking_pipeline/` 里的 Mask2Former（`mfaytin/mask2former-satellite`）写出 0–5 类用地，再走现有重建。优化器仍然只读 `landuse`，不读影像，也不调用分割网络。

## 1. 语义分割

按坐标构建新场景时，分割发生在数据阶段，权重不在仓库里，区域精度和易混类别也还没有在本文记录。预置苍南、永嘉仍读取已经做好的类别 csv。`data_tools/landuse_tool.py` 只读取类别 csv。当前苍南场景的来源文件名是 `satellite_27.501662_120.194639_r0.90km_z18_crop_epsg3857_routing_coarse_mask_downsampled.csv`。文件名表明这是一张粗分类掩膜，不是某个可替换的模型接口。

因此现在不能回答「要不要把某个模型再训准一点」。要先补三件事，再决定是换模型还是只靠人工修正：

- 模型名称、输入影像和输出类别。
- 在本区域上的误差：哪些类容易混，例如农田和裸地、道路和空地。
- 类别是否够用。加油站、变电站这类地物不在现有六类里，不能假装当前掩膜已经认识它们。

分割升级放在数据阶段，产出仍然是一张与现有主栅格对齐的 `landuse`。优化模块不读取影像，也不调用分割网络。

## 2. 点选标注

决策者往往不能从影像上断定一块地是农田还是加油站。除了自由画圈，还要能点一下就把附近同类范围标成不可建设。

目标交互：

1. 选择「添加不可建设区域」。
2. 在地图上点击。
3. 系统标出点击位置附近的房屋、农田或用户认定的一块范围。
4. 用户可以接受、缩小或删掉这块标注。
5. 接受后的范围进入同一次优化的硬约束，规则与现在的手绘禁区相同。

分两段做，避免一开始就绑死新模型。

第一段不引入分割网络。点击落在现有 `landuse` 的某个格子上，把与该格子连通、且类别相同的区域标出来。农田点下去得到附近农田，建筑点下去得到附近建筑。这一段能先用，因为它只读取场景里已经有的类别图。

第二段才接入可点选的分割模型。点击作为提示，模型返回一块掩膜，再对齐到 1 m 主栅格。模型可以换，接口只保留「影像 + 点击 → 局部掩膜」。加油站这类细类如果模型不认识，就允许用户把点选结果标成「人工不可建设」，不伪造一个新的 landuse 编号。

点选结果是场景上的标注层，不是每次优化临时算出来的目标。重新优化时可以沿用，也可以清掉。它不改写原始 `landuse_1m.npy`，和手绘禁区一样在搜索前合成。点击、画圈、进货原点和拖动方案怎样收成同一份地图编辑，见 `markdown/FRONTEND_IMPLEMENTATION_SPEC.md` 的「地图操作与算法数据」。

## 3. 施工成本

温州设计院要求选址考虑施工和运输，而不只是现在的三个目标。下面三项分开建模，各自先有输入、输出和报告，再决定是否参与搜索。

### 3.1 地形与交通

已经考虑的部分：站址矩形里的高程越不平，地形目标越大；离最近道路越远，道路目标越大。

还没有的部分：

- 坡度。方差小不等于坡度缓，一整面斜坡也可以方差不大。需要用 DEM 在足迹内计算坡度，并给出一个可配置上限。超过上限的方案不可行，或者在报告里单独标出。
- 山上不建不是一律禁止。山体和农田默认都按坡度、离道路远近，以及从道路开车能否过去来判断。侧栏仍可以把它们改成一律不可建设。
- 交通是否方便。现在只有到道路的直线距离，没有「进得去」的判断。这一条和下面的进站路径一起做，不另造一个含糊的交通分数。

### 3.2 物流成本

决策者指定一个进货或拉货原点，可以是地图上的一个点，也可以是一条已有道路上的点。对每个候选站址计算把物料从原点运到该位置的成本。

这是一个子问题，不放进引导式多目标搜索的内部循环里现写。成本接口在 `modeling/construction_cost.py`，路径仍由 `modeling/logistics_cost.py` 计算。

运输量不乘单价，也不把高差乘进长度。问题定义里只保留三项独立的米制量，以后进入搜索时各自作为一个目标：

```text
road_m          沿道路的长度
offroad_m       离开道路的长度
access_rise_m   进站路径上的高程变化绝对值之和
```

`RoadHaulCost` 的离路两段是直线，只报长度。决策搜索与方案报告使用 `HaulField`：站址到道路只走可建设格子，用多源 Dijkstra 按逐步水平距离和高程差惩罚选择路径，再分别报告路径长度和累计高差。具体代价和配置见 `markdown/MODELING_MODULE_SUMMARY.md`。没有通路时不退回直线。

路径选择的高程惩罚系数只控制找路偏好，不合并运输指标、不替代多目标比较。道路段仍没有路宽，本实现不读路宽或遥感。足迹坡度还不是硬约束。

这三项加上脚印平整度，就是决策界面引导式多目标搜索的默认目标，各自最小化，不加权。需求点距离仍会计算并写入方案表，但需求点目前是随机的，默认不参加比较；侧栏可以打开 `include_demand`。进站固定八连通，只改变格子走法，不增删目标；口径见 `markdown/GUIDED_SEARCH.md`。到道路的直线距离不在其中。CMA-ES 的三个目标不变。需求点目前仍是随机点；以后换成新能源负荷预测时，只换 `demand_points` 的来源，不改 `demand_distance` 这个名字。

### 3.3 从道路到房屋的路径要平坦

房屋尽量靠近道路之后，还要看从道路接到房屋的那段路是否平整。直线距离短，中间仍可能爬坡。

当前实现：

- 站址到道路的路径只经过可建设格子，由多源 Dijkstra 按逐段水平距离与高程变化惩罚选出。
- 沿路径读取 DEM，计算高差和最大坡度。
- 选定路径后分别报告水平长度、累计高差和最大局部坡度；最大坡度超过上限只作警告。道路接入点直接投影到道路折线段，不靠固定间距离散道路点。

沿路长度、进站长度和进站累计高差都进入引导式多目标搜索，指标不合并；完整口径见 `markdown/GUIDED_SEARCH.md`。

坡度阈值、原点单位运价和「山体是否禁止」都放在配置里，不写死在损失公式中。

## 4. 实施顺序

已经做完的第一版：点选连通区域、足迹坡度报告、物流成本报告和路径、直线进站坡度警告、分割模型占位接口、山体默认不可建设。施工成本接口已把路上和离开道路分成两个单价。站址到道路的成本路径已改成可建设格子，并按坡度加价。它仍不是搜索目标。

后面按这个顺序做，一次只做一步：

1. 把坡度做成能不能盖房子的主要约束，超过上限的方案不可行。运输成本不用来筛选。
2. 进站路径已改成沿可建设格子做高程感知的最短路径搜索；车辆通行坡度目前只报告警告，尚未设为硬约束。
3. 沿路长度、进站长度和进站累计高差已进入决策界面的引导式多目标搜索，彼此不合并。
4. 分割模型。补齐模型身份和误差之后再换类别图。

每一步单独验收：输入输出写在对应权威文档里，并有一个小网格测试。不把未记录的临时输出当成正式结果。

### 5.5 输入、计算与输出契约

#### 问题输入与配置

- `RoutingProblem` 接收标准 DEM、landuse、道路段及类别、独立永农掩膜、网格身份与数据版本。道路 Voronoi 和随机需求点不进入本轮四目标。
- 起终点保存 WGS84 经纬度及解析后的局部米坐标。计算只使用局部坐标，前后端复用现有场景变换，并检查两份表示一致；不凭影像观感添加坐标偏移。
- 最大档距、塔基控制半径、最大允许转角是任务显式输入，缺失报错，不从旧项目像素参数推导。前两者为有限正数，转角为有限的 `0–180°`。
- 道路退距沿用现有普通道路及高速/匝道配置入口和距离来源，隧道不因中心线成为地表道路。初始值通过 `load_default_config()` 读取，本次覆盖值完整保存；不额外继承站址的水体退距、农田/山体开关或运输通行限制。
- 新增算法配置段由 `config/default_config.json` 保存默认数值，dataclass 只定义字段和类型，插件 schema 从该配置读取。seed、种群规模、评价预算和搜索算子参数属于算法配置；不增加地类价格、跨越价格或目标加权系数。
- 主计算预算采用目标评价次数，以便固定 seed 复现；另记录耗时。参数的实际数值在实现阶段写入唯一 JSON，文档不复制数值默认值。

#### 统一几何与评价

- 单条线路用可变长度的新增塔位数组 `[N, 2]` 表示，两端固定接入点放在问题配置中。允许 `N = 0`；起终点不放进可变基因，也不受塔基圆和新增塔之间 `2r` 检查。
- 建模层提供批量 PyTorch 评价接口，四目标返回 `[B, 4]`。不同塔数通过有效位标记打包，补齐位不参与目标和约束；数组及硬几何辅助可使用现有 NumPy/Numba/Shapely 能力。首版不以 GPU 加速或反向传播作为完成条件。
- 选线目标顺序独立定义为 `tower_count`、`length_3d_m`、`bend_sum_rad`、`crossing_3d_m`。对外曲折度可显示为度，排序和内部计算统一用弧度，不修改站址公共目标名单。
- DEM 高程采用统一的连续采样规则，明确像元中心、边界插值和无效值处理。非法输入不静默夹回场景；候选接点缺少有效 DEM 时不可行。
- 地物格子视为 1 m 像元方格。塔基圆与禁落塔格子的相交按整个方格检查，包含边界接触；不能只采样圆心、周界或格子中心。控制圆完整落在有效场景范围内。新增塔圆之间仍按 5.2 允许 `2r` 相切，不混淆两种边界规则。
- 线段穿格累计准确的参数区间，合并重叠区间后计算相交长度；不用旧项目固定像素间隔采样，避免漏掉窄道路或水体。沿像元公共边界行进时仍只计一次。
- 人工禁跨越区域按完整连接线检查，边界接触也判为违反；零长度接触不增加跨越长度目标，但不免除禁跨越检查。人工禁落塔区域只检查新增塔基圆。
- 重复相邻接点、零水平长度档、非有限坐标及越界在评价前明确识别。内生的无效候选可修复或淘汰，不能因一条坏候选中断整次优化，也不能变成可行解；用户正式输入错误直接报错。
- 硬约束按名称保留原始违规量，最终可行性要求逐项通过。搜索采用可行解优先比较，不把不同单位的违规量未经说明相加，也不把违规量混入四目标；需使用标量违规度时，按对应的自然尺度归一，公式和顺序在实现建模前写入建模文档。
- 初始化、局部修复、搜索评价和最终复核共用这一评价口径。修复只移动新增塔，失败候选保持不可行或淘汰，不以原位置兜底为合法。

### 5.7 重点回归案例与搜索扩展规则

#### 建模正确性

1. 水平位移为 `(3, 4)`、DEM 高差为 `12` 的单档：水平档距为 `5`、三维长度为 `13`。最大档距检查使用 `5`。其中水平相交长度为 `2` 时，跨越量为 `5.2`。
2. 平坦 DEM 的直线总转角为零；左转和右转分别累计。某一处超限时，即便总长度和总曲折度更小，仍不可行。
3. 塔中心在建筑外，但控制圆碰到建筑、道路控制范围、水体或永农时不可行。仅导线经过前三类时允许并计算跨越，经过永农不新增罚分。
4. 两基新增塔中心距离小于、等于、大于 `2r`；固定接入点与新增塔分开处理。不能仅因 `D_max < 2r` 就拒绝可能合法的零塔或一塔问题。
5. 建筑与道路范围重叠、同一道路多来源重叠、线段沿栅格边界经过时并集长度不重复。穿过窄地物也不能因固定采样间距漏计。
6. 同一个人工多边形分别设为禁落塔和禁跨越，产生不同约束效果；固定端点不得被修复逻辑移动。
7. DEM 采用坡面时与手算高程一致；修改高程会改变三维长度，但不会改变同一水平路径的转角。每塔坡度仅报告，不改变四目标或可行性。

上述案例使用合成小网格和独立手算/几何参照，不复制整套评价器作为测试答案。覆盖批量打包的无效补齐位与边界输入。

#### 塔数范围与多目标搜索

- 在初始种群构造后保存下界、有效参考线路塔数与初始上限。参考线无效时记录原因，继续在预算内尝试初始化和扩展，不宣告不存在线路。
- 扩展由搜索驱动：没有可行解，或当前上界上的候选仍具有非支配价值时允许放开。还应保留确定性的边界探查机会，避免「最少塔已经可行」导致所有较多塔方案从未被评价。
- 扩展时保留已有可行非支配方案，更新可变塔数范围，新增候选继续使用相同评价器；不重置端点、地物参数或数据版本。具体探查周期、增长步长与停止条件作为算法配置/公式写清，数值只进入默认 JSON。
- 专门构造「少塔可行，但多一批塔可降低跨越量」的案例，验证不会找到首个可行解就停止扩大机会。构造需要回折才能绕开的禁跨越区域，验证参考线的「不掉头」没有变成全局禁令。
- 用可手算的无遮挡场景检查确定的直线解，用小型离散候选集枚举检查非支配选择；随机复杂场景报告优化差距，不把返回前沿表述为已证明的全局完整前沿。
- 停止记录区分预算耗尽、配置的收敛条件、取消和输入失败。固定 seed 的复现比较使用相同输入身份、配置、后端和评价预算，时间只作为测量值。

### 5.8 软件验收、性能与交付

#### 前端和任务链路

- 起终点可分别点选或输入经纬度，表单与地图同步；两端清晰标记为固定接入点，新增塔显示控制圆。
- 两类人工区域使用不同名称和样式。参数与端点变化生成新的评价身份；切换场景、启动新任务后旧响应不得覆盖当前状态。
- 地图显示候选线路与新增塔，选中后展示四目标、每档水平/三维长度、转角、跨越量、逐项可行性及塔基最大坡度。界面明确显示「净空未校核」。
- 前端不计算线路目标或 Pareto，不改变现有北向相机和手势限制。首版不引入额外路由框架，也不把线路塞进站址方案模型。
- 复用现有任务状态和取消确认机制；`cancelling` 期间仍占用场景。运行失败保留旧结果，成功且结果身份匹配后再替换显示。
- 历史实验按 `problem_type` 使用对应读取器。线路几何和指标可独立回读；旧站址实验继续使用原来的字段与展示。
- 首版助手快照标明当前「选址/选线」模式，说明选线入口、目标和限制。选线模式不套用站址目标排名，也不接受站址编辑提案；未新增对应工具前，不能承诺替用户点选接入点或启动选线，不能调用站址 `run_search` 冒充。实现这些用户可见能力时同步助手说明与评测。

#### 大场景性能

先测量后优化，按合成小网格、真实较小 UTM 场景、楠溪江 9000×9000 场景推进。第一次真实验收使用显式固定 seed 和评价预算，不批量扫参数。

- 标准 1 m 数据作为最终评价依据，不静默降分辨率。若初始化需要较粗导航结构，明确它只是候选生成辅助手段，结果仍回到原始 1 m 数据检查。
- 数组优先只读或 mmap；道路距离缓冲按任务构建一次，批量评价不重复建场。不创建像元数乘道路线段数、或种群数乘整幅影像的全量广播。
- 几何检查按塔基局部窗口和线段实际经过的格子计算；对大数组的转换、哈希和复制分块处理，避免为了生成测试答案同时加载多份全图。
- 报告上下文准备时间、评价吞吐、总评价次数、总运行时间、主机峰值内存、结果数量和最终硬约束违规数。首版没有 GPU 数据时明确记录 CPU 执行，不以环境存在 CUDA 作为加速证据。
- 真实场景测试只读正式场景，所有输出进入新的独立实验目录。未跑完不写完成实验记录，已跑完按既有格式追加 `EXPERIMENT_LOG.md`。
