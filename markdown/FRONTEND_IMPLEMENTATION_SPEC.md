# 温州设计院选址软件前端实施规格

选线模块化改造保持现有页面行为与 HTTP/任务配置。`use_routing_controller.ts` 集中管理任务、历史、场景切换与过期响应；`routing_controls.tsx` 和 `routing_results.tsx` 只接收状态/回调，`routing_workspace.tsx` 负责组装。编辑状态、产物解析与地图图层保持原有职责。控件标签/顺序/默认值/禁用条件、刷新恢复、取消、404 处理及共享北向地图不变，不增加算子选择功能。

> 状态：SPEC
> 目标：交给另一个 Agent 实现前端，不在本文中直接编写代码
> 适用范围：`frontend/` 及其直接依赖的 API 适配，不改动算法数学实现

## 1. 摘要

前端需要把“选址问题 → 决策者配置 → 算法运行 → 候选解比较 → 结果解释”串成一条清晰的工作流。使用者首先应该知道当前问题使用了哪些数据、约束和目标，然后能够用表单完成一次可复现的运行，最后能在地图、指标卡、Pareto 关系和候选解详情之间切换，而不必阅读 JSON 或服务器日志。

第一阶段优先复用当前已有的实验产物和 API：静态地图 PNG、Pareto HTML、CSV/JSON artifact，以及 `/jobs` 的任务状态接口。等真实算法插件接入后，再逐步增加交互式地图和更细的决策支持功能。前端不实现目标函数、约束或算法逻辑。

## 2. 目标用户和使用场景

主要用户是温州设计院参与选址决策的工程人员和项目负责人。他们关心：

- 当前选址区域和数据是否正确；
- 候选点是否满足不可建设区域约束；
- 地形、道路和需求点目标之间如何权衡；
- 算法是否完成、使用了什么配置；
- 哪些方案可行、方案之间的取舍是什么。

他们不应该被迫理解 Python 模块名、raw pose、normalization 或内部队列。技术细节可以在“运行详情”或“数据详情”中展开，但不应成为主流程的第一层信息。

## 3. 设计原则

1. **先解释问题，再允许运行。** 页面必须先展示区域、数据图层、约束和目标顺序，避免用户在没有上下文时直接提交参数。
2. **一个页面只突出一个主要动作。** 配置页的主要动作是“检查并运行”，结果页的主要动作是“选择和比较方案”。
3. **表单是领域配置的唯一入口。** 不要求用户手写 JSON；组件由插件或配置 schema 生成字段，并显示单位、默认值和校验错误。
4. **结果先看可行性，再看优化取舍。** 不可行解不能与可行 Pareto 解使用相同的视觉权重。
5. **所有数字都带语义。** 例如 `road_distance` 显示为道路距离，单位为 `m`；`n_feasible` 显示为可行方案数，而不是只显示字段名。
6. **前端保持薄。** `api.ts` 负责 HTTP，组件负责展示和交互，后端/算法负责计算。不要在 React 中复制目标函数、Pareto 判断或坐标转换。
7. **先保持浅层目录。** 当前前端文件数量不大，按功能拆成清晰模块即可；只有出现第二个复用者时才新增共享目录或抽象层。

## 4. 当前代码基础和实施边界

当前前端已经具备以下基础：

- `App.tsx`：应用外壳、健康状态，以及“问题与运行 / 实验结果”视图切换；
- `problem_overview.tsx`：问题概览；`problem_snapshot.ts`：实验产物到 `ProblemSnapshot` 的适配；
- `job_workspace.tsx`：插件列表、任务配置和提交；`run_monitor.tsx`：配置页的任务轮询；`run_status.ts`：状态文案；
- `config_form.tsx`：按 JSON Schema 渲染中文分组配置表单；`config_check.ts`：提交前检查；
- `experiment_browser.tsx`：实验目录；`result_explorer.tsx`：方案地图、详情和表格；`solution_record.ts`：方案 CSV 适配；
- `api.ts`：前端请求和 API 类型；
- `generated/api.ts`：由 OpenAPI 生成的类型文件，不手工维护。

实现 Agent 应在这些模块上演进，不要重新建立第二套请求封装、第二套配置表单或第二套实验 artifact 读取逻辑。目录和职责总览见 `markdown/CODE_MAP.md`。

当前稳定可用的接口是：

```text
GET  /api/v1/health
GET  /api/v1/plugins
POST /api/v1/jobs
GET  /api/v1/jobs/{job_id}
GET  /api/v1/jobs/{job_id}/result
GET  /api/v1/experiments
GET  /api/v1/experiments/{experiment_id}
GET  /api/v1/experiments/{experiment_id}/artifacts/{artifact_id}
DELETE /api/v1/experiments/{experiment_id}
```

当前 `demo.algorithm` 用于验证任务链路；真实算法插件接入前，前端可以使用 fixture 或现有 `outputs/` 目录完成界面开发，但不得把 Demo 结果伪装成正式算法结果。

## 5. 目标页面和工作流

### 5.1 页面结构

主界面是可平移缩放的公开卫星世界地图，选址范围、禁行区和带朝向的帕累托建筑足迹叠加在局部网格上。底图地址集中在 `frontend/src/map/basemap.ts`。决策侧栏只保留定位、建筑尺寸和开始优化，不使用复杂路由框架：

```text
应用外壳
└── 决策地图
    ├── 定位选址区与建筑尺寸
    ├── 开始优化（site.guided_search，不填写目标权重）
    └── 帕累托建筑足迹与道路距离、平整度
```

上方「主页」里的构建或更新场景数据写入 `scenes/`。侧栏只显示场景是否已准备，开始优化只读取该场景。「软件更新」在与「文件」「视图」「编辑」同级的「设置」页，不放进地图右侧。点开后要输入这台机器 `.env` 里的 `UPDATE_PASSWORD`。确认后快进拉取当前分支，并重新启动本仓库的页面和接口；工作区有未提交修改、不能快进、或已有更新在进行时拒绝，不停止正在运行的进程。该更新流程使用 `restart.sh`，只支持 Linux 服务器；Windows 本地可启动 API，但不能用此功能更新。页面会断开，内存中的任务清空。新进程没有就绪时退回拉取前的提交再启动。更新会重启开发服务器，Vite 客户端在服务器恢复后会自动重新载入页面，所以提交时把这次的更新号存进 `localStorage`，载入后接着轮询。有结果后弹窗用大字显示「更新完成」「更新失败，已退回原版本」或「更新失败」，下面是脚本消息和当前版本号，同时弹出提示，并清掉存下的更新号。页面已重新载入时按钮是「知道了」；没有重新载入时是「刷新页面」，因为旧页面里的前端代码要刷新才换成新的。提交后 60 秒内状态里一直没有这次的更新号、也没有更新在进行，判为「更新没有开始」，原因看 `outputs/dev-servers/update.log`。助手不能代为更新。

「文件」里的「导入案例」列出 `outputs/` 中已完成的实验目录。导入读取该目录的 `solutions.csv` 和 `pareto_solutions.csv`，在地图上显示可行帕累托足迹，并从 `resolved_config.json` 的 `modeling.rect_w_m`、`modeling.rect_h_m` 恢复建筑尺寸。目录里有 `site_form_snapshot.json` 时，同时恢复其中已有的山体/农田策略、农田代价、禁区、可行域、进货原点、需求点比较和进站斜向开关；缺这份文件时不改当前侧栏，并提示这次结果没有保存当时的约束。「导出全部方案 CSV/JSON」导出当前地图工作区中的全部方案，不受当前选中项影响；CSV 使用 UTF-8 BOM 和中文表头，位置使用 CGCS2000（EPSG:4490）经纬度（小数度，6 位小数），方向只保留宽边方位角，可行性用“可行/不可行/未知”表示，不包含局部 x/y、弧度角或局部搜索来源列；JSON 记录局部坐标、同一组 CGCS2000 经纬度（`longitude_deg`、`latitude_deg`，坐标系写在 `geographic_crs`）、角度单位、场景、建筑尺寸和导出时间。经纬度由场景记录的投影网格（新场景为 WGS84 UTM，封存场景保留 EPSG:3857）反算得到 WGS84 数值，不做基准转换直接作为 CGCS2000：两者相差厘米到分米级，远小于 10 m DEM 和 OSM 道路的精度。当前工作区没有方案时两个导出项禁用。「导出优化场景 PNG…」在当前场景已准备时可用，没有方案时也可以导出场景地图。它打开独立设置窗，本次勾选的 GIS 图层、Pareto 层级、推荐编号、截图范围和中文文件名只影响下载的图片。删除先要求再点一次确认，然后移除该实验目录。不能删除输出根目录之外的路径，也不能删除正在写入的当次优化目录。桌面端导入案例面板默认宽度为 560 px，左侧、顶部和底部分别保留 380 px、148 px 和 18 px，并允许内容纵向滚动；宽度不超过 900 px 时恢复流式宽度。

顶部「主页」功能区和左侧工作栏的优化操作区都提供「清空方案」。两个按钮调用 `MapWorkspace.clearDisplayedSolutions()`；「开始优化」保持主按钮，「清空方案」使用次级样式。没有方案或优化任务正在启动、排队、运行时按钮禁用。按钮清空不再二次确认，成功提示统一为「已清空当前方案，历史优化结果已保留。」

清空只移除当前工作区中的全部候选方案及其选中项、详情卡和连接线、对比项、AI 推荐高亮和编号、当前加载案例 id、方案报告和运输路径、方案预览、调整状态、重算状态及其他只依附于旧方案的临时结果。场景数据、DEM/道路/GIS 图层及其显示设置、禁区和可行域、土地类型微调、进货原点、建筑尺寸、农田策略、优化参数、地图视口、历史实验文件、助手对话和长期偏好均保留。清空不刷新页面，不重新挂载地图，也不删除后端数据。

方案导入、优化结果读取、局部优化合并和方案报告请求都捕获同一方案代次号。目标重算按本文「方案调整与数据版本重算」的评价 key 驱动。清空或开始另一项会产生方案结果的操作时推进代次；响应返回时只有代次仍匹配才允许写回，避免清空后旧方案或旧指标重新出现。优化任务活动期间，UI 清空入口禁用；Agent 清空确认也由同一执行入口明确拒绝。

侧栏面向决策者，只放这几项：

- 定位选址区；
- 建筑宽度和高度；
- 开始优化，固定调用 `site.guided_search`，用引导式多目标搜索直接比较三个目标；
- 任务状态，以及选中方案的道路距离、地形平整度、需求点距离和可行性。

「文件 → 另存当前实验…」允许用户输入中文名称，将当前保留的全部方案保存为独立案例，之后从「导入案例」重新打开。保存包含多样性滑块隐藏但未删除的方案、手动及局部优化方案；已删除方案不从原始结果中补回。优化、构建或方案调整期间，以及没有保留方案时禁止保存。确认时固定方案集合、位姿、场景、建筑尺寸和约束，后端按当前场景统一重新评价所有保留方案再保存，不依赖前端可能过期或四舍五入的指标，也不重新运行优化。

每次另存创建新的案例 id，自定义名称只用于显示，同名保存也不覆盖旧实验。保存当前用地策略、手绘范围、退距、原点和需求点开关，记录来源案例；不复制整套场景矩阵。重新打开保留手动标记、来源关系和原有层级，包括保留下来的不可行方案，默认显示第一档。保存时的位置和指标成为新案例的恢复基线。历史 `pareto_layer` 保持不变以供显示，但 `is_pareto` 和 `pareto_solutions.csv` 按当前重新评价的可行非手动方案以及本次启用目标重新计算；手动方案完整保留在工作区，不进入该前沿。当前场景数据之后变化时，仍按评价 key 重新评价。保存失败显示原因且不留下半成品案例。

橡皮擦和详情卡共用单方案删除流程，适用于当前显示的搜索、导入、局部优化和手动方案。橡皮擦命中顺序为进货原点、收藏点、方案、人工土地图斑、用户范围；方案悬停显示红色边线和删除提示，单击后保持橡皮擦模式。删除同步移除保留集合、对比和推荐引用，并清除编辑预览和待发送附件；删除选中方案时关闭详情和路径，选中原位置的下一个方案，没有则选上一个。只剩隐藏方案时保留缓存和原点锁定，可提高多样性档位重新显示或另存；整个保留集合为空才执行统一清空。优化运行或拖动时两个入口均拒绝删除，橡皮擦在目标重算期间也拒绝删除。切换档位或另存回读不得恢复已删除方案。历史实验和独立收藏记录保留；重新导入历史案例可以恢复其中的原始方案，未保存的手动方案删除后不能从历史恢复。单方案删除不加入 Ctrl+Z 撤销。

### 5.2 问题概览：基础展示

左侧工作栏提供「方案多样性」三档水平滑块，左侧为低、右侧为高，默认 1。第 1 档只显示原有第一层可行帕累托方案；第 2 档累计显示前两层；第 3 档累计显示前三层。旁边标明当前档位、各层数量和颜色：第一层沿用青绿，第二层橙色，第三层紫色；选中态仍以白色边框区分，AI 推荐填色保留，边线仍标明所属层。

分层规则以 `markdown/GUIDED_SEARCH.md`「结果显示分层」为准。滑块只改变已加载结果的显示，不修改搜索配置或重新运行搜索。新结果导入或整场景优化完成时回到第 1 档。未显示的层保留在本次结果缓存中，收回再展开不丢失已修改的姿态。地图点击、方括号切换、详情卡、对比、导出和助手快照只包含当前显示的方案；隐藏选中项时切回第一个可见方案，并移除已隐藏的对比和推荐标记。优化或拖动时滑块禁用；重算不禁用，重新显示的方案按评价 key 自动重算。清空方案和切换场景同时清除缓存，滑块不能恢复已清空的方案。收藏点和手动方案不参与分层；手动方案在所有档位始终显示。

局部优化仍按原流程只追加其第一层代表方案，并在本次缓存中标为第一层；不因旋转、拖动或追加局部结果而重新划分原搜索的前沿层级。层级描述的是载入时的搜索结果，不是当前改动后重新排序的全局前沿。

页面打开后，用户首先看到问题概览卡片：

- 区域名称或实验名称；
- 栅格范围、宽高、分辨率和坐标约定；
- DEM、不可建设区域、道路和需求点四类数据是否已加载；
- 当前数据来源和 seed；
- 建筑矩形尺寸；
- 目标顺序：`dem_soft`、`road_distance`、`demand_distance`；
- hard feasibility 规则：不可建设区域 hard count 必须为 0。

地图区域至少提供一张基础预览，并显示图例：

- DEM：连续色带；
- obstacle mask：半透明红色；
- 道路：深色线；
- 需求点：橙色点。

第一阶段可以直接使用实验目录中的 PNG。数据尚未准备好时，显示“缺少哪一项”和下一步动作，不显示空白地图或伪造随机数据。

### 5.3 配置与运行：决策者输入

配置表单分为四组，组标题使用中文，字段旁显示单位和说明。

#### 数据与实验身份

- 实验名称；
- 数据输出目录或实验标识（如果后端负责目录，则只显示实验名称）；
- 数据版本/来源摘要；
- 随机 seed。

#### 站点和约束

- 建筑矩形宽度 `rect_w_m` 和高度 `rect_h_m`（110 kV 变电站占地）。默认值取插件 schema，即 `config/default_config.json` 的 `modeling` 段。决策地图启动时从 `site.guided_search` 的 schema 读取尺寸和 `include_demand` 作为初始状态。进站八连通固定开启，不从这份 schema 关闭，读到之前尺寸框留空，不能提交；
- 是否只在可建设区域生成需求点；
- hard feasibility 说明和当前阈值；
- 分辨率字段只读展示，避免用户误改已经生成的数据网格。

#### 目标偏好

- 三个目标的权重或偏好配置；
- 明确显示权重总和必须为 1；
- 提供“均衡偏好”快捷入口；
- 提供“偏地形/偏道路/偏需求点”的预设，但预设必须展开为可查看的实际权重；
- 说明所有目标当前按最小化解释。

#### 算法和运行参数

- 算法选择；
- 算法特有参数由 JSON Schema 生成；
- device、迭代次数、起点数量等参数只在对应算法提供 schema 时显示；
- 显示预计产物类型，不在前端硬编码算法内部参数。

表单提交前必须经过“运行前检查”：

- 必填项完整；
- 数值在合法范围内；
- 权重总和正确；
- 数据产物已存在；
- 实验名称不会覆盖现有结果，或用户明确选择覆盖。

检查失败时在字段附近显示原因，并保留用户输入。检查通过后，唯一主要按钮为“开始运行”。

### 5.4 运行状态：用户需要的操作

引导式搜索的运行消息必须由后台实际解析出的设备和演化后端生成，现有运行页与地图工作栏直接显示 `job.message`。GPU 张量演化显示显卡名称、CUDA 编号和「GPU 张量演化」；显式 NumPy 后端配合 CUDA 评价时显示「CPU NumPy 演化，GPU 评价」；CPU 回退或显式 CPU 显示「CPU NumPy 演化」。进度文案不写内部算法名称。不能根据浏览器、请求中的 `device` 或机器是否有 GPU 推断实际执行方式。

消息同时标出当前阶段：CPU 距离场读取/构建、初始化与梯度引导、每代进化、最终精确报告、图件与文件输出。最终报告和文件输出有独立阶段，避免第 90 代完成后仍显示正在进化。设备描述在一次搜索开始时取得，逐代复用，不轮询 NVIDIA 工具或额外同步 CUDA。完成后实际设备、后端和描述保存在 `normalization.json`；显存占用和瞬时 GPU 利用率不单独作为任务采用 GPU 的判据。

运行提交后显示：

- 实验名称和 job id；
- 状态：排队中、运行中、已完成、失败；
- 当前阶段；
- 进度条；
- 最近一条消息；
- 配置摘要；
- 失败原因和重新运行入口。

第一阶段不做复杂日志终端。公开任务错误显示阶段、类型、说明和任务 ID，Python traceback 只写服务端日志。任务轮询只能由运行状态模块负责，其他组件不得各自轮询同一个 job。

如果后端尚未支持取消任务，界面不要显示假的“取消”按钮；可以保留未来扩展位置，但当前只提供“返回配置”和“重新运行”。

### 5.5 结果探索：最终方案可视化

结果页采用“实验列表 + 结果详情”的两栏布局。

左侧实验列表显示：

- 实验名称；
- 算法名称；
- 完成时间（如果 manifest 提供）；
- 解数量、可行数量、Pareto 数量。

右侧详情按以下顺序展示：

1. **结果摘要**：总解数、可行解数、Pareto 解数、是否存在可行解；
2. **主地图**：新实验不带候选地图。旧实验目录里若仍有 `pareto_footprints_map.png` 等 PNG，按原顺序切换显示；没有时只显示说明，不把实验判为失败；
3. **方案选择**：选择一个候选方案后显示 `x`、`y`、`theta`、三个 soft objective、hard metrics 和可行性；
4. **目标权衡**：旧实验目录里若有 Pareto 3D HTML 则显示；新实验没有该文件。二维对比仍读取方案表；
5. **方案表格**：支持按可行性、Pareto 状态和目标值排序；
6. **原始产物**：JSON、CSV 提供查看或下载链接。

视觉层级必须遵循：

- 可行方案使用主要颜色；
- 不可行方案降低透明度或默认隐藏；
- 选中的方案使用明显高亮；
- 约束违反使用红色，但不能只靠颜色表达，必须有文字或图标说明；
- 地图、表格和指标卡点击一个方案时同步更新。

### 5.6 结果可视化的分阶段范围

第一阶段（必须完成）：

- PNG 地图预览；
- Pareto HTML iframe 或新窗口打开；
- 摘要指标卡；
- 方案表格或 CSV 查看入口；
- 单个方案详情；
- artifact 缺失时的明确空状态。

第二阶段（在真实算法结果稳定后）：

- 浏览器内二维 Pareto 图；
- 图、表、详情之间的联动选择；
- 按可行性和目标范围过滤；
- 两到三个候选方案并排比较；
- 地图图层开关和图例控制；每个图层必须独立初始化、显示或隐藏，不依赖前一个图层的可见状态。

当前决策地图的 GIS Layers V1 从顶部常驻「图层」按钮打开独立浮动面板。面板标题栏支持拖拽，折叠后仍可移动，关闭后重新打开保留本次页面内的最后位置；标题栏按钮不触发拖拽。面板包含地形分析的 DEM 高程；土地利用的农田、建筑、道路区域、水体；建设约束分析的建设可行性；交通与规划的道路网络、行政边界、手绘禁区、手绘可行域。卫星底图、规划区域边界和优化候选方案固定显示，不加入开关。原「视图」页不再重复提供四类土地利用开关。

地图和 PNG 导出的中心线图层统一称为「道路网络」，GIS 面板显示场景道路 metadata 中的供应来源；旧 OSM 场景显示 OpenStreetMap，试验替换为高德后显示高德。内部快照键 `osm_roads` 和导出键 `osm` 保留，二者都指向当前 `road_segments_local.npy`，不能从内部键推断当前供应来源。外部道路试验替换的入口与限制见 `markdown/DATA_MODULE_SUMMARY.md`「外部道路 Shapefile 试验替换」；网页统一导入见本文「方案调整与数据版本重算」。

「行政边界」显示区县级（admin_level=6）和乡镇/街道级（admin_level=8）的边界线与名称标注，数据来自 `GET /api/v1/scenes/{scene_id}/admin-boundaries` 返回的 WGS84 GeoJSON，前端直接作为地图 source，不经 `SiteFrame`。区县级用较粗实线，乡镇级用细虚线，两级同显。底图样式没有字体，图层画不了字，名称标注用 DOM marker 落在产物自带的标注点上（与推荐徽标同一模式），PNG 导出时用 canvas 文字补画（与排名徽标同一模式）。开关默认开启；隐藏只影响显示，切换场景时按新场景重新请求。请求完成且要素非空才向助手声明图层可用；缺文件或范围内没有数据时如实提示，不把场景就绪等同于图层可用。图例注明「非官方界线，仅供空间参考」；永嘉等场景乡镇级边界在 OSM 中缺失时如实缺画，不用第三方数据补齐。PNG 导出图层列表包含「行政边界」，使用同一 source 绘制；导出请求携带实际 GeoJSON，即使地图隐藏该层或刚完成加载，边界线和名称也必须一起导出。数据来源与提取口径见 `markdown/DATA_MODULE_SUMMARY.md`「行政边界显示数据」。

DEM、道路网络、建设可行性和永久基本农田默认关闭，四类土地利用沿用原默认状态，手绘禁区与手绘可行域默认开启。首次进入和切换场景时永农图层不显示；用户打开后，普通地图刷新不会再关掉。隐藏只影响显示，不改变 pose-objectives、site-report 和优化里的永农约束。DEM 使用场景真实最小/最大高程图例，单位为 m，透明度默认 60%，面板不显示原始 DEM 分辨率或重采样说明。四类土地利用开关在常规宽度下按农田/建筑、道路区域/水体两行两列排列，空间不足时退化为单列；颜色、可用状态和独立开关语义不变。道路网络直接显示 `road_segments_local.npy`，经现有 `SiteFrame` 转到地图坐标；它与 landuse 的道路区域是两个独立图层。禁区和可行域共用 `forbidden-zones` source，只通过 `kind` 过滤显示；隐藏不删除 `SiteEdit` 数据，也不改变 `searchConfig()`。启用任一范围绘制工具时，自动恢复该类型可见。图层开关和透明度只更新地图，不提交优化任务。

「文件 → 导入数据」打开统一数据导入窗口，可以分别或同时上传道路和永农。永农部分上传包含同名 shp、shx、dbf、prj 的 ZIP，服务按 prj 内容识别源坐标系，经 `data_tools/scene_coordinates.py` 转到场景元数据记录的投影 CRS，再按 `data_metadata.json` 的仿射变换栅格化到当前 1 m 网格。预览不写正式禁建文件；确认后替换 `protected_farmland_mask_1m.npy`、`protected_farmland_import.json` 和紫色叠加图。GIS 面板可显示、隐藏、替换和删除该层。隐藏只影响地图，不取消硬约束。没有这层数据的旧场景保持原约束。PNG 导出的图层列表包含「永久基本农田」，使用同一张叠加图。

永久基本农田不并入土地利用类别 1。即使用地策略把普通农田设为允许建设，永农格子仍禁止建筑 footprint。新建进站道路使用同一掩膜再按 `data.protected_farmland_access_width_m`（默认 4 m）做半宽距离缓冲；Gate 到道路中心线的新建短线也不得进入该范围。已有路网仍按现状运输，与永农重叠的格子记在导入说明里供核对。找不到合法进站路径的站址仍按原有不可达规则判为不可行。场景上有排队或运行中的任务时，不能替换或删除这一层。

#### 土地类型微调

「编辑」页增加土地类型工具，可选择农田、建筑、道路、水体，以及「去除水体」。道路图斑写入土地利用类别 3（道路区域），不改道路中心线。「去除水体」只把圈内当前水体像元改成其他，不覆盖农田、道路或建筑。选中工具后，按住鼠标左键沿区域拖动勾画，实时显示无顶点圆点的虚线预览，松开后闭合并进入草稿；绘制手势与禁区、可行域的画圈一致。只能在选址范围内绘制。右键点击已保存图斑可删除整块图斑；绘制中不提供右键菜单，也不支持右键结束、删除节点或取消草图。

完成图斑会立即作为当前场景的持久修正保存，并非 `SiteEdit` 的禁区或临时显示覆盖。后端以当前 `landuse_1m.npy` 的首个未修改版本作为场景基准，按保存顺序将修正图斑烧录到 1 m 栅格；每个被图斑触及的像元设为该图斑类别，后画的图斑覆盖先画的图斑。更新有效 `landuse_1m.npy`、按类别生成的土地利用 PNG 和 `obstacle_mask_1m.npy`；原始输入和其它场景不受影响。之后的优化和建设可行性计算直接读取更新后的有效栅格。农田/建筑/水体颜色复用现有土地利用图层。重新构建该场景会用新构建的数据重置其人工修正。

修订存放在场景目录，刷新页面后仍然保留：`landuse_base_1m.npy` 保存第一次修订前的场景基准，`landuse_edits.json` 保存带稳定 id、类别和局部米制 ring 的修正记录。服务提供 `GET/POST/DELETE /api/v1/scenes/{scene_id}/landuse-edits`、`PUT/DELETE /api/v1/scenes/{scene_id}/landuse-edits/{edit_id}`；POST 新增类别为 1（农田）、2（建筑）、3（道路区域）或 5（水体）的图斑，PUT 替换指定图斑的 ring，DELETE 按 id 删除指定图斑，DELETE 集合则恢复场景基准并清空所有修正文件。前端载入已准备的场景时调用 GET，把已有图斑读回来，不调用集合 DELETE。已保存图斑的边线默认不画；选中农田、建筑、道路或水体工具时画出，助手提案正在预览地图改动时也画出。橡皮擦模式也显示边线，点击已保存图斑删除整块；不再提供右键删除菜单。所有点都必须有限且在 1 m 栅格边界内；无效 scene、类别、id 或 ring 返回明确错误。成功写入或删除后更新前端记录并重新加载着色栅格；请求失败时明确提示且不静默继续。重新构建该场景仍会重置人工修正。

建设可行性是土地分类、山地/农田策略、手绘范围、道路退距和水体退距的只读 1 m 网格预览。红色表示建筑不宜覆盖的格子，包括土地硬约束、永久基本农田、遥感道路类别 3 与普通道路中心线并集按 `road_setback_m` 扩展出的退距、高速地表段及匝道共用的独立退距，以及类别 5 水体按 `water_setback_m` 扩展出的退距。它不是某个旋转站址 footprint 的完整可行性判定。优化栏在「道路最小退距（m）」下方有「水体最小退距（m）」，两者默认都是 5，允许 0。普通「水体」图层只画类别 5 本身，不把退距缓冲画成水体。前端把 `searchConfig()` 中的山地/农田策略、农田代价、手绘禁区、手绘可行域、道路退距和水体退距提交给 `/api/v1/scenes/{scene_id}/construction-feasibility-overlay`；同一数值也进入引导式搜索和 `pose-objectives` 重算。同一场景、同一永农版本和同一组约束已经有图片时，关闭图层只隐藏，再次打开直接显示，不重新请求。永农导入、替换或删除、土地图斑修改、场景重建、策略、手绘范围或退距变化后不能继续用旧图。勾选「建设可行性」的 PNG 导出使用这份当前预览。后端复用 `policy_from_form()`、`polygons_from_form()`、`compose_constraint_masks()` 以及建筑道路退距和水体退距掩膜，将可覆盖格渲染为 `#2DB88A`、15% alpha，将禁建格渲染为 `#EB626D`、35% alpha。进程内按场景文件签名和上述约束缓存 PNG；小场景另外保留一份土地、道路栅格和道路/水体距离场，退距变化时只重做阈值比较。超过约 400 万格的场景不保留距离场，也不在后台预取；这些场景的退距从道路和水体格子按同一 1 m 欧氏半径向外扩展，红绿格子与距离场上的 `<=` 比较一致。场景和默认约束就绪后，不超过这个格子数的当前场景会在浏览器空闲时预取同一张图，但不打开图层；预取完成前打开时，面板显示「正在生成」，并等待这一次请求，不另发一次。平移缩放、浮窗操作和普通图层显隐不请求，也不重设未变化的道路和站址数据。未完成的旧请求不能覆盖新结果。正在显示的图片不会因缓存淘汰被提前释放，离开页面或缓存被替换时才释放 Blob URL。单一 RGBA 图层位于土地利用/DEM 之上、手绘范围边界和候选站址之下。进站路径不使用这张预览里的道路退距或水体退距。主页「准备当前场景数据」对当前打开的任何已就绪场景都会重新构建，并融合 `masking_pipeline/data/regional/` 下 `fclass=water` 的水系面，再按遥感水体补全同目录的 `water_lines`。遥感没有水的允许河段仍沿官方线留下较窄走廊，融合前的道路和建筑格子不改成水体；普通打开场景仍然直接复用。这些宽度不是测绘实测。

第三阶段（确有需求再做）：

- 交互式 1 m 栅格地图；
- 候选 footprint hover 和点击；
- 结果标注、批注和导出报告；
- 方案收藏和多人协作。

不要在第一阶段引入 GIS SDK、全局状态框架或复杂图表依赖。现有 PNG/HTML artifact 已经足以验证工作流。

### 5.7 候选站址人工调整

决策地图允许对已经选中的 Pareto 候选方案做一次人工微调，但人工调整不是重新优化，也不能在前端重新实现评价公式。

- 拖拽只改变候选方案中心坐标，建筑宽高和当前朝向保持不变；
- 边界校验必须使用旋转后矩形的四个真实角点。拖拽到规划区域外时，把中心限制到最近的合法位置，保证完整矩形仍在区域内；
- 角度输入对用户使用度，内部 pose 和 API 仍使用弧度。方案信息只显示“方位角（宽边）”，并通过它的 1° 数字步进控件调整朝向，数值变化后立即生效；旋转后若完整矩形越界，则拒绝该角度并保留上一个合法角度；
- 每个候选方案保留优化结果中的原始 `x`、`y`、`theta`，用户可以一键恢复原始方案；
- 拖拽过程中只更新地图。松手、应用角度或恢复原始方案后，调用 `/api/v1/scenes/{scene_id}/pose-objectives` 重新评价，并明确显示加载、成功和错误状态；开始重新评价时把该方案目标标为「重算中」，禁止把旧指标显示成新位置结果；
- 精确重算请求必须带上当前场景、建筑尺寸、山体/农田策略、农田代价、手绘禁区、可行域和可选进货原点。后端返回前不得用前端估算值或模拟值代替真实评价；`site-report` 只补充施工坡度和进站路径报告；
- 重新评价结果复用现有指标列表，以“原值 → 调整后值”表达变化。规划区域内违反建设约束的方案可以保留，但必须明确标记为不可行；
- 本功能不改变引导式多目标搜索的目标、约束或 Pareto 集，不写入数据库，不修改候选方案对比图表。

地图上已经有候选方案时，新增、删除、修改、撤销或恢复禁区、可行域只把这些方案标为「待重评」，不自动调用 `pose-objectives`。从「导入案例」打开历史结果时，恢复已保存的表单并直接显示案例保存的目标值和可行性，不因此标为待重评，也不调用 `pose-objectives`。保存值不证明它在后来修改过的场景中仍然可行；后续移动、旋转或改变输入仍按原路径评价，后续禁区、可行域或土地修订变化仍标为待重评。缺少历史表单时保留当前设置并明确提示。评价键若因撤销而回到该方案已经评价过的版本，则恢复为当前有效。没有候选方案时不出现待重评，也不因此增加评价请求。用户可在优化栏点击「重新评价旧方案」，或直接点击「开始优化」。手动重评复用现有接口，单批仍最多 200 个方案，并覆盖当前保留的各帕累托层；返回时约束版本或位姿已经变化的结果丢弃。待重评不是「重算中」。拖动、改角度、改尺寸、策略、原点、退距和土地图斑保存仍按原有路径自动评价。

方案详情、收藏详情和方案对比图不再展示道路距离；地形、进站长度、累计高差、可选沿路长度和需求点距离仍按既有条件显示。底层 `road_distance` 字段和建模函数保留，不能以界面隐藏为由删除历史数据或改变优化目标顺序。

当前选中方案的详情卡与候选变电站中心之间使用一条非交互式青绿色引导线建立视觉对应。站址端点由 MapLibre 把候选中心投影到浏览器视口坐标，卡片端点根据详情卡实时 DOM 边界自动选择最近边缘；地图移动、缩放、站址调整以及卡片拖拽、缩放或内容布局变化时同步更新。站址移出地图、详情卡关闭、端点尚未完成测量或站址落在卡片内部时隐藏引导线。该线仅是界面提示，不写入选址数据，也不表示道路、供电线路或其他真实地理连接。

AI 助手、GIS 图层、候选站址详情和方案对比四个浮动窗口共用一份页面内显示顺序。窗口首次显示、关闭后重新打开或切换到另一候选站址详情时自动置顶；按下窗口任意可见区域、通过键盘聚焦窗口内容、开始拖拽或调整大小时也置顶。普通数据刷新、AI 流式回复、GIS 图层状态变化、地图平移缩放和已打开对比面板增减曲线不改变已有层级。层级切换只调整窗口显示顺序，不重置位置、尺寸、折叠状态或内容；SchemeCard 引导线仍处于地图提示层，不覆盖其他浮动窗口。

桌面端 GIS 图层面板首次显示在地图工作区右下方，默认底部余量为 72 px，并与 AI 助手的默认水平中心对齐；常规 310 px 面板宽度下等效为距工作区右侧 155 px。实际位置继续受工作区边界和顶部安全距离限制。用户手动拖动后保留该位置，普通重渲染、AI 助手移动和图层状态变化不触发复位。宽度不超过 900 px 时沿用现有流式布局，不强制套用桌面端偏移。

`/pose-objectives` 接收当前编辑和一个或多个候选 pose；单个方案在接口内形成一行 `[1, 3]` 位姿。它调用 `experiments.launch_site_run.evaluate_form_poses()`，后者复用搜索的约束装配、`evaluate_pose_batch()` 和 `compute_hard_constraints()`，返回方案表同列的软目标、硬指标和可行性；不启动搜索，也不在接口内重写目标或约束公式。

### 5.8 苍南 / 永嘉场景切换

顶部工具栏常驻两个预置地区按钮：苍南对应 `cangnan`，永嘉对应 `yongjia`。场景列表和 frame 都来自 `GET /api/v1/scenes`；前端不复制苍南坐标，也不把切换实现成只调用 `flyTo()`。选择 ready 场景时使用返回的 frame 重新挂载场景地图并定位真实边界；选择未构建场景时仍可按原始 GeoTIFF 预览 frame 定位，但不请求场景图层或提交优化。「主页」里的「准备当前场景数据」对当前打开的任何场景都可点，已就绪时再点会按该场景保存的原始文件重新构建。其他任务进行中仍禁用。

切换场景时统一清空上一场景的草稿、禁区、可行域、进货原点、候选方案、方案卡、比较、推荐、报告、土地类型修正缓存、图层资源和历史导入标记，并把 `SiteEdit.sceneName` 改成新 id。构建任务活动期间两个地区按钮和优化入口都禁用。预置场景构建成功后重新读取场景列表时按 id 保留当前选择，不回到默认苍南；构建失败时显示 Job 错误且该场景继续为未就绪。按经纬度新建场景的选择规则见 5.9。

历史方案导入前读取该实验的 `resolved_config.json` 或 `site_form_snapshot.json` 中的 `scene_name`。缺少场景身份的旧结果和属于另一场景的结果都拒绝导入，不能把一套局部坐标解释到另一套 SiteFrame。搜索任务返回结果也只写回提交时仍处于同一场景的工作区。

### 5.9 按坐标构建场景

「文件」菜单第一项是「新建场景…」，打开应用内弹窗，不新开浏览器标签。弹窗标题是「新建场景」，副标题是「通过地理坐标生成站址基础数据」。表单提供纬度、经度（并排）、边长（米，默认 1800）以及可选场景名称。场景名称可以是中文。边长必须是 2 到 20000 之间的偶数米。一格是 1 m，网格等于边长乘边长，表单不提供高度和宽度。提交前显示网格尺寸、1 m 分辨率和当地 WGS84 UTM 网格说明。卫星下载范围由目标网格自动计算，完整覆盖标称边长。主按钮是「构建场景」，请求插件 `site.build_scene`。表单不暴露 `zoom` 和 `road_buffer_m`，后端使用各自的默认值 18 和 500。校验仍用 `parseBuildSceneConfig()`。

任务状态和轮询留在 `MapWorkspace`。关闭弹窗或按 Escape 只隐藏窗口，不取消任务；再次打开时如果这次构建还在，继续显示同一任务的阶段、进度、状态说明和已用秒数。进度只来自任务记录，不使用本地假进度。构建进行中禁用表单和第二次构建，场景切换和优化入口仍按任务活动状态禁用。终止复用现有取消接口；运行任务显示“正在取消”，直到执行器确认退出才解除占用。失败时保留输入和可读错误，并可用上一次参数重试。

成功后重新读取场景列表，按结果里的 `scene_id` 选中新场景并加载它的 frame 和地图数据。找不到该 id 时停在提示，不退回苍南。之后的编辑和优化沿用左侧「选址优化」工作栏。预置苍南、永嘉仍由顶部选择，并用「主页」里的「准备当前场景数据」走 `site.prepare_scene`。左侧工作栏不再放经纬度构建表单。

### 5.10 导出优化场景 PNG

「文件」菜单在 CSV、JSON 导出后面提供「导出优化场景 PNG…」。当前场景尚未准备完成时该项禁用。点击后打开应用内设置窗，不新开浏览器标签，也不取消正在运行的优化。

设置分四组。GIS 图层沿用地图现有类别和配色：卫星影像底图、DEM 高程、农田、永久基本农田、已有建筑、遥感道路、水体、道路网络、行政边界、建设可行性、手绘禁区、手绘可行域、进站路径、进货原点和收藏站址。底图默认勾选。其余项默认跟随当前是否显示。当前场景没有对应数据时，该项禁用并写明原因。选址范围边界始终保留。

Pareto 第 1、2、3 层可以任意组合，包括一层都不选。方案来自当前 `diversityPool`，只按已有 `paretoLayer` 筛选；不重算层级，不重跑搜索，也不改多样性滑块或 `edit.poses`。没有方案的层级显示数量 0。可选「显示推荐方案排名编号」。编号和颜色沿用当前推荐顺序、`RECOMMEND_COLORS` 和 `PARETO_LAYER_COLORS`，被筛掉的方案不画编号。

截图范围默认是完整选址范围，使用当前 `SiteFrame` 边界并留出边缘；也可以使用当前地图中心、缩放和旋转。相机方向和图片北向标记遵循下文「米制网格与地图显示」。文件名可以是中文，默认「当前场景名称-优化方案分布图」，例如「楠溪江选址规划-优化方案分布图.png」。下载前去掉 `\ / : * ? " < > |` 等不能用于文件名的字符，避免空名称和过长名称，并补上 `.png`。

导出使用已经打开的 MapLibre 地图。地图创建时设置 `preserveDrawingBuffer`，这样 WebGL 画布在绘制后仍能读出。推荐编号是 HTML Marker，导出时按地理坐标画到 Canvas 上，不依赖 `getCanvas()` 包含这些标记。底图瓦片按匿名跨域加载；Esri 影像响应带 `Access-Control-Allow-Origin: *`。导出等待地图 `idle` 且视口瓦片加载完成，不用固定延时。画面无法读取、卫星底图空白、输出为空或资源报错时提示失败，不显示成功。图片下方写场景名称、已导出的图例，以及开启卫星底图时的影像来源。

导出过程中按钮显示「正在生成图片…」，并禁止重复导出和切换场景。若为本次图片临时打开未加载的图层或移动视角，结束、失败或取消后都会恢复原来的图层、方案和相机。关闭设置窗只隐藏窗口。

## 6. 前端模块设计

保持 `frontend/src/` 浅层目录，每个文件只表达一个用户功能或一个稳定技术职责：

```text
App.tsx                 应用壳、导航、全局健康状态
api.ts                  HTTP 请求和领域类型
config_form.tsx         JSON Schema 配置表单
job_workspace.tsx       插件选择、运行前检查、任务提交和轮询

problem_overview.tsx    数据、区域、目标和约束概览
result_explorer.tsx     方案筛选、比较和联动展示
styles.css              页面布局、颜色、状态和响应式样式
generated/api.ts        OpenAPI 生成文件，只重新生成，不手改
```

如果 `job_workspace.tsx` 或 `experiment_browser.tsx` 继续变大，应按用户功能拆出子模块，而不是把所有代码移动到一个泛化的 `utils` 文件。React 采用组合式功能组件即可，不要求为了“面向对象”而使用 class component；状态必须封装在所属功能模块中。

建议的组件接口以领域对象为中心：

```text
ProblemSnapshot
RunConfig
RunStatus
ExperimentRecord
ArtifactRecord
SolutionRecord
```

组件不应直接依赖后端返回的任意字典。API 层负责把 OpenAPI 响应转换为这些稳定的前端类型，字段语义和单位写在类型旁边或对应注释中。

## 7. 数据和 API 适配要求

### 7.1 已有接口的使用规则

- 任务、场景和实验请求统一经过 `api.ts`。Agent 对话经过 `frontend/src/agent/agent_api.ts`，因为那份契约单独维护；
- API 错误转换成用户可读的中文消息；
- 组件不能拼接后端 base URL；
- artifact URL 只来自后端 manifest，不根据文件名自行猜路径；
- PNG 使用 `<img>`，HTML 使用受限 iframe，JSON/CSV 使用链接或文本查看器；
- artifact 不存在时显示可恢复的空状态，不让整个结果页崩溃。

### 7.2 问题概览的接口扩展

当前 API 还没有正式的问题概览接口。实现 Agent 可以先使用 fixture 或从已有 `resolved_config.json`、`data_metadata.json` 和实验 artifact 组装只读概览，但应把读取逻辑放在 `api.ts` 或独立 adapter 中。

后续建议增加：

```text
GET /api/v1/problem/context
```

返回至少包含：

```text

grid: { width, height, resolution_m, coordinate_system }
layers: { dem, obstacle, roads, demand_points }
constraints
objective_order
data_source
seed
```

如果该接口尚未落地，前端必须明确标记“来自实验产物”或“演示数据”，不能把 fixture 当作正式数据。

### 7.3 运行配置和结果类型

运行配置至少要能表达：

```text

seed

```


字段缺失时显示“未提供”，不要在前端推导或猜测指标。

### 7.4 地图操作与算法数据

地图上的点击、拖拽和画范围不各自对应一套算法接口。交互只改一份地图编辑；算法只从这份编辑里读它认识的字段。经纬度停在地图模块，算法看到的都是场景 1 m 局部坐标：原点在选址范围左上角，x 向东，y 向南。

当前代码由 `frontend/src/map/site_edit.ts` 的 `SiteEdit` 承担算法编辑。禁区、可行域、点选同类、进货原点和拖动方案都只改它。土地类型微调是持久的场景数据修正，不进入 `SiteEdit` 或助手提案；它通过本节 5.6 的 landuse-edits API 更新场景有效栅格。下面是 `SiteEdit` 的发送口径，新功能按此加，不另开传输。

一份地图编辑包含这几类，坐标都是局部米：

```text
scene_name
building        宽度、高度
policies        山体策略、农田策略、农田代价系数
marks[]         { id, kind, x, y }
regions[]       { id, kind, ring }
poses[]         { id, x, y, theta }
```

`marks` 和 `regions` 用 `kind` 区分用途。现在有三种：`origin` 表示进货原点，最多一个；`exclusion` 表示不可建设范围；`feasible` 表示可行域。两种范围都至少三个顶点。点选同类用地得到的圈写成 `exclusion`。禁区和可行域只出现在「编辑」页，不放在地图右侧。

地图操作只改这份编辑，不直接调用建模或搜索：

| 操作 | 改动 |
| --- | --- |
| 进货原点 | 写入或替换 `kind = origin` 的标记。编辑内部和请求继续使用局部米制坐标；工作栏和成功提示只通过 `localToLngLat` 显示六位小数的 WGS84 经度、纬度 |
| 禁区、点选同类 | 追加一条 `kind = exclusion` 的范围 |
| 可行域 | 追加一条 `kind = feasible` 的范围 |
| 画圈、方框 | 禁区和可行域下面都有这两个二级选项。画圈松手闭合。方框先点一个角并显示对应颜色的圆形标记，移动时显示半透明填充和虚线边框，再点对角线另一角完成；矩形取这两点的外接边，轴与局部坐标对齐 |
| 删除范围或原点 | 范围侧栏按钮按 id 去掉；进货原点状态区在存在原点时显示「清除」。橡皮擦使用专属光标，按 5.1 的命中顺序选择目标；悬停高亮目标并提示点击删除，单击后保持橡皮擦模式。工作栏清除和橡皮擦删除原点共用同一流程 |
| 土地类型微调 | 在「编辑」中选择农田、建筑、道路、水体或「去除水体」；道路写入土地利用类别 3，不改道路中心线。普通图斑整块覆盖；水体纠正只改圈内当前水体。按住左键拖动自由勾画，无顶点圆点的虚线预览，松开后进入草稿，手势与禁区/可行域画圈相同。切换橡皮擦后点击草稿图斑删除整块，重叠处优先删除最后绘制的一块；不提供右键删除。保存后修订保留在场景目录，刷新页面会丢失未保存草稿，只有重新构建场景才恢复基准。已保存图斑的边线默认不显示，选中土地类型工具、橡皮擦或助手提案正在预览地图改动时显示。橡皮擦悬停提示「点击删除土地类型图斑」，优先命中进货原点、收藏点、优化方案、人工土地图斑，最后命中禁区或可行域。此操作更新场景土地利用栅格和建设掩膜，不属于 `SiteEdit`，不随禁区/可行域请求发送 |
| 拖动方案 | 只改该方案的 `x, y`，朝向和尺寸不动 |
| 点选方案 | 只改变当前查看的方案 id |

离开选址范围的点不写入编辑。

删除只保留一个最近快照，类型是被删除的范围或进货原点；`Ctrl+Z` 只恢复这一个对象，不恢复整份旧编辑。重新手动设置原点或确认助手的 `set_origin` 后，旧的原点删除快照立即失效，不能覆盖新原点。原点只有在优化任务未处于提交、排队或运行状态且工作区没有方案时可编辑；否则地图点击设置、重新选择、工作栏清除、橡皮擦、`Ctrl+Z` 和 Agent 的 `set_origin`/`clear_origin` 全部使用同一锁定判断并明确拒绝。生成或导入的方案都与当时的原点绑定，任务结束后仍保持锁定；任务失败、取消或结束且没有方案时自动解锁。清空当前方案解除结果锁定，但保留原点和后端历史实验。范围擦除和其他地图浏览不受影响。清除原点时若当前工具是「进货原点」，自动切回拖拽。

原点清除或恢复不重跑搜索，也不清空、替换或重新编号已有方案。前端立即清掉旧单点报告，再用当前 `searchConfig()` 重新评价现有方案；重算结果只有在方案位姿和完整评价配置仍与发出请求时一致时才能写回。单点报告同样只接受当前 effect 的结果，避免快速清除、恢复或重设原点后旧运输路径和旧指标重新出现。无原点时，方案卡不显示「沿路长度」，方案对比也不显示「沿路」轴；原始历史指标仍保留为基线，但不能冒充当前配置的重算值。

### 7.5 收藏人工站址

收藏站址是独立于 `SiteEdit.poses` 的持久对象。它不参与搜索、Pareto、方案编号、历史案例导入或「清空方案」。地图上用独立图层和区别于算法方案的颜色呈现。详情卡调用现有单点评价接口，按当前场景约束和收藏自身尺寸显示可行性与目标值；未返回评价结果时不得伪造数值。评价不将收藏加入优化方案。

收藏的新增入口是优化方案详情卡的「收藏站址」，保存当前方案姿态；地图和收藏详情卡只选择、查看或删除已有收藏。完整建筑仍须位于当前场景的数据覆盖范围内。违反建设约束的收藏可以保存，评价后明确标记为不可行。

`favorite_points.ts` 负责坐标和朝向转换；`favorite_store.ts` 独立管理场景收藏的加载、选中和保存；`use_favorite_points.ts` 适配 React 和地图回调；`favorite_evaluation.ts` 组装并调用已有评价接口；`favorite_panel.tsx` 展示只读详情卡。`MapWorkspace` 只传递当前场景、配置和界面回调，不把收藏数组塞入 `SiteEdit`、Agent 快照或算法请求。地图叠层只绘制收藏方框、中心点和选中态。地图点击只选择已有收藏，不再新增或拖动。

场景加载和收藏写入均按本次场景访问代次校验，切换场景再切回时旧响应也不得回填。初始列表尚未读完或已有写请求进行时，新的写操作明确提示稍后重试；同一时刻只提交一个收藏写请求。保存失败保留上次已确认的收藏状态，错误显示在地图提示中。

每个收藏记录字段为：

```text
id
scene_id
longitude, latitude       WGS84 十进制度，持久化主坐标
width_m, height_m         创建时建筑长宽快照
bearing_deg               建筑长边方位角，北为 0°，顺时针增加，归一化到 [0, 360)
created_at, updated_at    UTC ISO 时间
```

地图局部坐标不持久化。读取时使用当前 `SiteFrame` 将 WGS84 转成局部米坐标。收藏从原点左上角起按场景隔离；切换场景时加载对应收藏，之后切回仍保留。新建、移动、旋转和删除均在后端成功响应后更新前端状态；请求失败时保留上次已确认的收藏状态并显示错误。

提供 `GET/POST /api/v1/scenes/{scene_id}/favorites` 和 `PUT/DELETE /api/v1/scenes/{scene_id}/favorites/{favorite_id}`。后端用 `FAVORITES_DB_PATH` 指定 SQLite 文件，默认 `outputs/user-state/favorites.sqlite3`；默认路径和环境变量中的相对路径均相对于仓库根目录，避免启动目录变化后读取另一份数据库。数据不放在 `scenes/`，也不受场景重建影响。同一运行服务的刷新和重启保留收藏；不同机器上的独立服务各自保存，不通过 Git 同步数据库。当前无用户身份认证，因此同一服务下的所有用户共享每个场景的收藏，可编辑和删除任一收藏。

编辑工具栏不再提供「添加收藏点」或「调整收藏点」。已有收藏仍可在地图上显示，点击方框或中心点打开详情卡。经纬度和方位角只读展示。新收藏只从优化方案详情卡的「收藏站址」保存当前方案的位置、尺寸和朝向。

「视图」中不再提供「收藏站址」入口。优化方案详情卡提供「收藏站址」按钮，把该方案当前的位置、尺寸和朝向保存为独立收藏；已收藏的相同姿态显示「已收藏」，避免重复保存。按钮不改变优化方案。收藏创建期间立即提示「正在保存收藏站址…」，按钮显示「收藏中…」并禁用重复请求；成功立即绘制收藏并打开详情卡，失败通过地图提示明确显示。边界校验失败同样直接提示，不依赖收藏面板是否打开。

收藏 API 同时接受预置场景和当前 `SCENE_ROOT` 下已完成标准产物发布的坐标新建场景，不读取原始四文件或大矩阵来验证身份；不存在、未完成或越出场景根目录的 id 明确拒绝。创建只执行轻量校验与 SQLite 写入，不等待目标评价。详情卡先请求目标评价，再复用缓存请求运输报告；目标值先显示，运输报告失败不抹掉已有目标值，避免并发重复构建同一距离场。评价请求使用当前场景完整约束、原点及收藏自身长宽、位置和朝向，仍由 `evaluate_form_poses()` 调用搜索使用的目标和硬约束函数，不新增收藏专用公式。未准备数据的场景可保存收藏，但明确显示暂不能评价；切换收藏、调整姿态、变更约束或关闭面板时中止旧请求，旧返回不得改写新状态。

收藏详情卡复用优化结果的卡片样式、决策变量与目标网格布局，支持拖动、缩放和关闭。卡内可切换已保存收藏。方位角只读，展示宽边北向 0°、顺时针增加的角度，不提供输入框或地图拖动。位置仍是已保存的 WGS84。卡片不展示仅适用于优化方案的对比、AI 和偏好按钮。删除仍走两步确认。

橡皮擦命中收藏方框或中心点时提示「点击删除收藏点」，点击后调用删除 API；成功后移除，失败保留并显示错误。收藏命中优先于下方禁区。面板删除仍保留确认流程。

经纬度落在当前场景外或场景栅格范围后来改变时，保留后端记录，在面板标记「当前范围外」，地图不绘制该点；不自动删除、裁切、夹取或迁移。恢复原场景范围后按 WGS84 再次显示。收藏列表中的删除针对单个对象，并在确认后调用 API。

验收覆盖：编辑工具栏没有新增或拖动收藏的入口；方案详情卡「收藏站址」仍可保存当前方案；点选已有收藏打开只读详情卡；只绘制方框和中心点；详情卡不能改方位角或拖动位置；橡皮擦和面板确认删除仍可删除收藏且失败时保留；刷新、服务重启和切换场景再切回后数据仍在；不同场景记录隔离；清空方案不删除收藏；场景重建不清收藏。

### 7.6 AI 助手

黑色菜单栏最右边的「AI」按钮打开「AI 助手」。窗口可以拖动和缩放，右上角能最小化。一条回复放在一个气泡里，换行留在气泡内，不按换行拆开。助手的气泡在左侧标志旁，用户的在右侧。回答按字出现，不等整段结束。标志用 Lucide 的机器人图标，许可是 ISC。它只提议改动。操作种类、校验和模型配置以 `markdown/AGENT_MODULE.md` 为准。

面板保留本轮对话，并把当前 `SiteEdit` 收成快照发给 `POST /api/v1/agent/chat`。返回提案时列出差异，地图用虚线预览新增或改动的范围、位姿和进货原点。用户点确认后，`applyOps` 才改这份编辑；提案里若有 `run_search`，接着走现有的 `site.guided_search` 提交；若有 `refine_pose`，走下文「局部优化」。拒绝则丢弃提案。提案发出后地图又被改过，则提案过期，不能确认，按钮变成「关闭」。确认、拒绝或关闭之后，提案框随即收起，结果作为一句助手消息留在对话里（「已确认，地图已更新。」「已拒绝这个提案，地图没有改。」）；发出下一句时，未处理的旧提案框也一并收起。

助手用单独的 `clear_poses` 提案清空当前地图上的全部候选方案。确认卡由前端按当前快照中的真实方案数生成「清空当前地图上的 N 个方案，保留历史优化结果、GIS 数据和用户绘制的约束。」；确认前不修改地图，确认后调用与两个按钮相同的 `clearDisplayedSolutions()`，不经过方案重算。`clear_poses` 必须是提案里唯一的地图操作，不和搜索、局部优化、选中或修改方案混用。清空造成快照变化后，依赖旧方案的其他待确认提案按现有快照戳机制失效。

助手面板有「对话」「偏好」两页。「偏好」页给每个目标设 0 到 5 的重要程度，保存到 `PUT /api/v1/agent/preferences/defaults`，并显示已记下几次选择。第一次使用、还没有选择记录时，推荐就按这组设定排序。助手回复按安全的 GitHub Flavored Markdown 渲染，用户消息保持纯文本；代码块和表格不得撑破气泡。

顶部「设置」工具栏提供「浅色主题」和「AI 助手设置」。「浅色主题」再点一次回到深色，选择存在浏览器 `localStorage`，默认深色。浅色只改面板底、文字、边框和输入框。顶栏西湖大学标志在 `frontend/public/`：深色用 `westlake-logo.png`，浅色用同目录的 `westlake-logo-ink.png`。卫星底图、用地类别、禁区、可行域、方案足迹、推荐徽标和对比折线不改。助手不能代为切换。对话框直接显示模型 API 配置和长期记忆，保存和切换都不需要管理员密码。API Base URL 显示 `.env` 中的上游地址，可以修改；本地 Docker 不把中继地址显示在这一项里。Model 显示当前生效值。其它由进程环境强制注入、且和 `.env` 不一致的字段不能在页面里改。配置来源由接口返回。API Key 不回显，输入新值即替换，留空则保留。保存模型配置不改变长期记忆；切换长期记忆也不提交未保存的模型字段。关闭长期记忆前必须二次确认，确认后清除文字记忆，但保留方案选择历史和目标偏好。关闭时中止正在生成的助手回复并丢弃尚未确认的记忆提案；地图编辑、偏好学习和推荐仍可使用。成功和失败提示留在对应区域，关闭窗口后清空。

方案小窗有「问 AI」按钮：打开助手，把这个方案作为附件放在输入框上方（「方案 3/20 ×」），并预填「分析一下这个方案」。助手窗口可能盖住方案小窗，所以没有附件且有选中方案时，输入框上方另有「＋ 附上方案 N/M」，点一下附上当前选中方案。发送时附件只随这一条消息发出，之后标签清掉，用户气泡上保留方案小标签。附件和分析口径以 `markdown/AGENT_MODULE.md` 为准。

方案小窗还有「记为我的选择」按钮：把当前方案作为选中项、地图上所有带目标值的方案作为候选，发给 `POST /api/v1/agent/preferences/choices`，成功后提示累计次数。带目标值的方案不到两个，或当前方案没有目标值时，只提示原因，不发请求。之后在助手里说「按我以往的选择推荐几个方案」即可用上这些记录。记录格式和推荐口径以 `markdown/AGENT_MODULE.md` 的「偏好推荐」为准。

助手回复带 `recommended` 时，地图按名次给这些方案上色：第 1 到 10 名依次为品红、橙、黄、绿、蓝、紫、粉、棕、青、灰（`RECOMMEND_COLORS`，`frontend/src/map/site_overlay.tsx`）。推荐的方案填充更实、边框更粗，中心放一个同色圆形徽标写名次（DOM marker，底图样式没有字体，图层画不了字），点徽标即选中；其余未选中的方案淡化。选中的方案仍用白色粗边框。推荐只存在页面状态里，刷新页面后需要重新问一次。地图左上角显示「助手推荐」图例，每行「第 N 名 · 方案 K」，点一行即选中该方案；方案小窗标题加「· 推荐第 N 名」。新的推荐覆盖旧的；点「清除颜色」，或地图上的方案被整体替换（导入案例、重新优化、重建场景、删除当前案例）时清空。局部优化加入的方案不清空已有颜色。

提案里带记忆改动时，差异下面列出「将记下」「将改写」「将忘掉」；确认时先复查长期记忆状态，再写记忆和改地图。长期记忆关闭后，助手不读取、不提议也不写入文字记忆。记忆的格式和规则以 `markdown/AGENT_MODULE.md` 为准。

编辑向外走三条通道：

1. 开始优化把整份编辑交给 `site.guided_search`。对应现有任务配置里的场景名、建筑尺寸、用地策略、`exclusion_zones`、`feasible_zones`、`include_demand`、`diagonal_access`、`origin_x`、`origin_y`。`include_demand` 默认关闭：需求点仍是随机点，不参加这次比较。进站固定八连通：斜向一步，斜步两侧都必须可建设，不能从障碍角切过。它进入搜索配置和 `site-report`，侧栏不能关闭。已经记下的方案目标保持原记录，重新评价或下一次优化才按八连通重算；当前选中方案的黄线仍会重画。没有可行域时整个选址范围都可搜索。搜索不在这一步重建场景栅格。任务成功提交后调用既有工具切换入口回到「拖拽」，同时取消未完成的范围或土地类型草稿并退出进货原点、方框、橡皮擦等编辑工具；参数校验或任务提交失败时保持当前工具。点击「开始优化」或局部优化后，工作栏里上一次的「已完成 · 任务已完成」立刻换成「排队中 · 正在提交」，新任务记录返回后再显示这次任务自己的状态。提交失败时恢复点击前的任务行，并用提示说明原因。任务运行期间地图上保留上一轮的方案，新结果读到后才替换；任务失败时旧方案留在原处。
2. 查看或拖完一个方案时，把该方案的 `x, y, theta` 和当前 `searchConfig()` 中的建筑尺寸、山体/农田策略、农田代价、手绘禁区、可行域及可选 `origin` 一并交给 `POST /api/v1/scenes/{id}/site-report`。报告端用搜索相同的掩膜合成函数取得同一 `HaulField`，从优化记录的 Gate 和前驱链回溯黄色运输路线，不再独立寻路，也不重跑引导式多目标搜索。优化 Worker 会把同一场景文件、约束掩膜和原点对应的距离场发布到共享场景卷；API 进程内未命中时优先复用它，条件变化后自动使用新键，损坏时回退重建。前端不额外预热，也不逐方案预计算报告。报告请求发出前清空上一条黄色路线；地图始终只画当前选中方案的一条路线。失败时保留方案已有目标值和可行性，并提示「方案 N 运输路线计算失败：原因」。选中方案或约束变化后，旧请求的返回不得覆盖新状态。报告返回的沿路长度、进站长度和累计高差显示 3 位小数，使 `0.1 m` 以下差异仍可见；CSV 精度不变。
3. 位姿、建筑尺寸、策略、范围、原点、道路/水体退距或道路/永农版本改变后，由评价 key 驱动，将当前约束和 `x, y, theta` 按最多 200 个一批交给 `POST /api/v1/scenes/{id}/pose-objectives`。接口按搜索同一口径调用现有目标函数和 hard constraint，不重跑引导式多目标搜索。返回的是方案表同样的列，前端写回目标值、禁建覆盖格数和可行性；结果回来前显示「重算中」，成功后显示“原值 → 调整后值”，失败时保留新位姿并明确报错。

点选同类用地的 `POST /api/v1/scenes/{id}/landuse-patch` 是场景查询，不是算法输入。它只把一个点击变成一圈顶点；前端把这圈写进 `exclusion` 之后，才和手绘禁区走同一条优化通道。

点选同类的类型、地图事件、场景查询和写入禁区的实现继续保留，但当前前端不在顶部「编辑」菜单或地图右侧快捷工具栏注册入口。

点中方案矩形时，特征小窗贴在该方框的右下角，平移地图或拖动方框时跟着移动。经纬度只通过 `localToLngLat` 得到；小窗不显示中心位置（m）。方位角是矩形宽边的方向，正北为 `0°`、顺时针；搜索内部的 `theta` 仍是 `[-pi, pi]`，`0` 表示宽边朝东。小窗中的方位角使用 1° 数字步进控件，点击上下箭头即旋转并重新评价；旋转后若完整矩形越界，则恢复上一个合法角度并提示原因。旋转角度仍作为决策信息显示。关掉小窗不取消选中，点选本身也不改折线图。小窗可以把当前方案加入对比，最多五个；折线图上每条线是一个方案，颜色按加入顺序取青、红、黄、绿、紫，不按方案序号，所以同时对比的五条线颜色各不相同。各项越小越好。侧栏需求点距离说明显示「预留接口」；勾选「比较需求点距离」后才显示这一轴。纵轴按这次全部帕累托方案固定，加入或去掉一条线不改变其他线的形状。折线用优化结果里的目标值，不改用当前点选方案的实时报告。

完整优化、历史结果导入和局部优化追加方案成功后，地图继续按 `SiteEdit.withPoses()` 的既有语义选中并高亮默认方案，但不自动打开方案特征小窗。只有用户点击候选矩形或推荐标记、点击推荐图例，或使用 `[ ]` 快捷键切换方案时才打开；关闭后保持当前方案选中，再次点击同一方案可以重新打开。小窗关闭时动态引导线同步隐藏，重新打开后恢复；普通地图平移、缩放、目标值更新和重绘不改变打开状态。

以后增加选点、画线或另一类范围时，加一种 `kind`，并在优化配置或单点报告里读这一种。不因为新操作再增加一个提交接口。算法不认识的 `kind` 直接报错，不静默忽略。显示开关、地图平移和定位选址区只影响画面，不进入这份编辑。

方案特征小窗和方案对比面板只允许通过标题栏拖动，并在桌面端通过右下角手柄调整大小。特征小窗默认 360 × 540 px，切换候选方案时重新贴近该方案；用户手动拖动后，普通地图平移和缩放不覆盖其位置。方案对比面板默认 680 × 400 px，内容区可滚轮滚动，折线图保持居中。两个面板都限制在地图工作区可见范围内；窄屏沿用静态响应式布局。关闭特征小窗后，再次点击同一候选方案必须重新打开。
#### 局部优化

助手提案里的 `refine_pose` 确认后，前端提交一次 `site.guided_search`，配置同第 1 条，只把 `feasible_zones` 换成方案中心周围边长 `2 × half_width_m`、裁到选址范围内的方框。读到这次的可行帕累托方案后不替换地图，按下面的规则挑出几个追加到地图末尾，原方案保留：

- 比较的目标与第 1 条的搜索相同：地形平整度、进站长度、进站累计高差；有原点时加沿路长度，打开需求点时加需求点距离。
- 对每个目标 k，在这一项比原方案小的局部方案里，取「其余目标上最大的变差」最小的一个；变差按该目标在局部方案和原方案上的跨度归一。同分时取 k 更小的。重复的只留一个，所以最多加目标个数那么多个。
- 某一项都不比原方案好时，这一项不出方案；一个都挑不出时只提示附近没有更好的点。
- 原方案还在「重算中」时无法比较，每个目标直接取局部最好的。

追加的方案 id 写成 `<实验目录>/<方案表 id>`，并带 `derivedFrom`（快照里是 `derived_from`）指向原方案。小窗标题写「方案 N/M · 由方案 K 局部优化」。完成后选中第一个新方案但不自动打开小窗，并提示是否有各项都不差于原方案的点。规则写在 `frontend/src/map/decision_run.ts` 的 `refinedChoices`。

## 方案调整与数据版本重算

方案的 `evaluatedFor` 记录场景、土地修订版本、道路产品 id、永农内容哈希、建筑尺寸、策略、范围、退距、原点、进站方式和位姿的评价 key。声明式驱动按最多 200 个请求，拖动中的选中方案暂缓；响应仅在 key 仍一致时写回，过期响应触发最新评价，失败可重试。任何约束及导入数据版本改变均使旧指标失效。场景身份由持久化 `frame_id` 和 `scene_revision` 描述；修正、道路/永农导入和删除均推进修订号。土地修订版本不依赖页面计数器：图斑保存、删除或场景数据刷新后，当前及重新显示的隐藏方案均须重新评价；发出请求和过期响应校验使用同一组版本。多样性滑块只在优化或拖动时禁用。报告同时传入道路、水体和高速退距，使用稳定请求 key 与 AbortController 取消过期请求。Worker 结果只携带实际读取的场景版本；版本缺失或修订不同需要重算，坐标网格不同禁止导入当前场景。

详情卡两步确认删除单个方案，同时移除隐藏层缓存、对比和推荐；删空清理全部方案临时状态，历史产物保留。编辑菜单的“添加方案”点地图创建手动方案，按当前全局建筑尺寸夹取中心，默认长边南北，自动评价并建立首次 baseline。手动方案使用独立颜色、始终显示且不计 Pareto 层数，PNG 分层筛选也不排除它。

“导入数据”包含永农 ZIP、道路 ZIP/RAR 两个可选文件及供应来源，分别显示预览、覆盖和类别统计，并在地图叠加候选道路。确认只更新上传项；非 OSM 来源可显式改回 OSM。图层面板显示当前可接入道路与永农重叠格数，道路按普通、匝道、高速和隧道分别绘制，后三者图例标注不可接入。重建保留导入道路并提示。

插件 schema 提供建筑尺寸、需求点开关和三类建筑退距的默认值；工作区在配置就绪后才发起目标评价。导入案例保留显式高速及匝道退距，搜索、重测和可建图请求统一传递，并进入评价 key 与缓存身份。

### 米制网格与地图显示

`SiteFrame` 是前端唯一的坐标转换，按后端 CRS 使用固定版本 proj4 处理 WGS84 UTM 和旧 EPSG:3857。它给出的经纬度数值同时作为 CGCS2000（EPSG:4490）使用，不做基准面改正；后端同一口径只在 `data_tools/scene_coordinates.py`。经纬度与局部坐标往返需与该模块的控制点相符。栅格叠加图在后端重投影为 EPSG:3857，并裁到正北研究域，图片四角取 `display_frame`。道路和建筑仍由实际模型网格转换，不能只变换 UTM 图片四角代替重投影。选址范围边界画的是 `study_domain.ring`，定义见 `markdown/DATA_MODULE_SUMMARY.md`「正北研究域」。建筑足迹的越界判断、拖动和旋转限位都以研究域为准，拖动时把中心限制到完整矩形仍在研究域内的位置。进货原点、选线接入点、禁区和可行域顶点仍只要求在模型网格内。道路矢量不裁剪。宽边方位角按候选位置的真北计算，收藏点仍保存经纬度及长边真北方位角，读写相互逆变换。

地图固定真北朝上、俯仰为 0。初次显示、切换场景、「定位选址区」及导入或优化后的自动定位均使用这个方向；UTM 场景的选址范围显示正北研究域，因此在地图上是正的；模型网格本身仍有网格北与真北之间的轻微倾斜，只在研究域外的边角带体现。鼠标右键/Ctrl 拖动、双指扭转、触摸俯仰和 Shift+方向键的旋转交互禁用，普通平移、缩放及双指捏合缩放保留。所有底图、栅格和矢量共用这一相机；局部坐标、数据矩阵及建筑真北方位角的口径保持不变。

完整范围 PNG 使用真北朝上、俯仰为 0 的相机；当前视角 PNG 使用当前相机。两种图片均在右上角绘制真北箭头。导出成功或失败后恢复原相机，沿用 5.10 的工作区恢复流程；恢复缩放和键盘交互时仍保留禁止旋转的设置。

方位角输入在编辑期间保留草稿，合法值即时旋转，失焦后才统一格式。导出 PNG 先用显示方案覆盖池中同 id 的旧位姿，再筛选层级。拖动的鼠标释放、工具切换、Esc 和组件清理共用结束逻辑，不能遗留调整中状态。失败批次重试只重新提交尚未成功的评价。

道路和水体退距使用独立输入草稿，键入期间不逐字符触发可行域计算；失焦或 Enter 提交合法数字，方向键和原生步进器完成一步后立即应用。失败评价有全局「重试全部失败评价」入口，成功方案不重复提交。

## 选线工作区

选线是与选址并列的问题模式，复用地图、场景选择、SiteFrame、北向相机和 Jobs 查询。起终点可分别地图点选或输入经纬度，双方同步，不自动挪动；端点是固定接入点。表单显式输入最大水平档距、塔基控制半径、最大允许水平转角，普通道路与高速/匝道退距从插件 schema 取初值。

绘制区域区分「禁止落塔」与「禁止跨越」。地图展示线路、固定接入点和新增塔基圆；选中方案展示四目标、每档指标和塔基坡度，始终标明「净空未校核」。前端不计算目标或 Pareto。保存任务配置和历史线路产物，回读不改写历史指标。参数/场景代次变化后，迟到响应不能覆盖新结果。选线状态独立于 SiteEdit，助手不接受站址提案代替选线操作。实现阶段与验收见 `markdown/DECISION_REQUIREMENTS.md`。

选线工作区已接入地图顶部的模式切换。`frontend/src/routing/` 按编辑状态、产物解析、图层和面板分工，`WorldMap` 只挂载选线图层和点选回调，同一地图实例与北向相机继续复用。工程参数未设置默认值，算法/道路默认值取插件 schema。运行期间配置与模式切换锁定，取消确认后释放；刷新按场景保留的任务 id 恢复，已保存结果按自身参数显示。旧站址历史列表过滤线路实验，选线历史只读取同场景线路产物。状态轮询通过 `use_job_polling.ts` 与任务页共用，过期异步响应复用 `SolutionGeneration` 丢弃。

选线保留共享文件、主页、视图、编辑和设置工具，隐藏站址专属编辑；两类区域分别支持画圈和方框，禁落塔为褐色、禁跨越为红色。绘制完成及提交任务前校验多边形顶点、面积和自交，错误指出区域并要求重画。起终点可拖拽调整，点选时显示当前光标位置。工作栏右边缘支持拖动或键盘调整宽度，选址和选线共享页面内宽度；窄屏按布局自动适配。

地图默认显示全部可行 Pareto 线路，选中与对比线路突出显示；对比线路的地图颜色与折线图一致。勾选线路或在详情卡加入对比时显示可拖动、缩放的折线图；四目标按本次全部可行 Pareto 线路分别归一化，数值越小、线越低，不能跨目标比较绝对数值。结果表按任一目标升序或降序排列，并可恢复原顺序；保留原线路编号、选中与对比身份，不改结果或搜索。线路结果可导出 JSON 和 CSV；表格排序不更改导出顺序。

地图悬停线路显示四目标及指向档段的已保存指标；悬停塔位显示坐标、高程、转角和坡度，悬停端点显示当前接入点坐标。点击线路、塔位或端点打开可拖动、缩放和关闭的线路详情卡，提供逐档指标、加入对比和「问 AI」；结果过期时标明旧配置，始终说明净空未校核。

选线配置在高级参数之外显示迭代次数和每代候选数量，并说明初始化不计入代数，每一代包含子代、选择以及该代排到的局部搜索和全局注入。结果面板读取本次摘要中的实际演化代数、搜索评价次数和初始化次数；旧摘要缺少这些字段时不推算。读取历史仍保留原算法配置，没有迭代次数的旧配置按评价次数和种群换算代数。高级参数内的「恢复当前算法默认参数」显式应用当前插件 schema 默认值，不改变接入点、工程参数和区域。

高级参数新增「搜索策略」。当前插件默认使用 PILOT 选线策略，默认启用 hybrid A*/RRT 初始化、精英局部搜索和条件式全局注入；standard 仍可显式选择作为对照。选择 PILOT 策略时，界面显式设置 NumPy、CPU 和兼容的评价后端，并禁用不兼容设备/演化选项；「RRT 初始化」复选框按默认配置初始为启用，可单独关闭。切回 standard 时清空迁移机制列表，保留其他参数。CPU 参考策略额外显示初始化模式和初始化评价上限，模式从插件枚举读取；切回 standard 同时将初始化模式恢复为 legacy。迁移参数分组随任务完整提交与回读，不将所有研究参数展开到普通控件。旧后端未提供该字段或 RRT 参数时不显示对应空白输入/开关。预算说明同时涵盖内部试探与局部/全局搜索，启用机制以保存配置为准。

恢复的任务返回 404 时，停止该任务轮询并清除对应场景的失效任务 id，解除输入和历史读取锁定，明确提示用户读取已保存实验或重新运行。不能把失效记录当作成功、失败或取消的算法结果；临时网络/服务错误仍可重试，不因此删除任务身份或旧线路结果。

算法高级参数区从插件 schema 读取执行默认值及枚举，区分数值、后端枚举和逗号分隔的设备列表。旧实验读取后保留原参数，重新运行时补齐当前新增执行参数；不改写旧线路指标。显存预算和批次是执行控制，不改变工程约束或四目标。

PILOT CPU 混合初始化显示为「PILOT 混合初始化」。默认配置已显式启用 A* 和 RRT；RRT 复选框只切换 RRT，保留其他已配置机制；离开混合模式移除其 A* 声明。CLI 可通过显式配置进行初始化来源消融。界面不承诺质量收益，旧四模式和历史值保留。

PILOT 参考策略的高级参数显示当前完整启用机制摘要；历史加载保留所有机制与 core 参数，RRT 复选框只增删自身，不能清掉交叉、变异或局部/全局搜索。非 RRT 研究组件沿用默认机制列表或通过显式任务配置做消融，界面不增加一组重复默认参数。standard 仍对应空机制列表，不能把提供组件等同于求解质量已提高。

### PILOT 张量执行配置

选线高级参数允许 PILOT 选择 tensor 演化与 tensor 评价，并填写显式 CPU/CUDA 设备列表。切换演化到 tensor 时同步评价后端；改回 reference/compiled_cpu 评价时同步 NumPy 与 CPU，避免保存无效混合配置。默认配置使用 tensor/tensor 与 CPU 设备；用户显式切换到 PILOT 时仍可从 CPU 参考设置开始。界面说明初始化和规划器仍在 CPU；启用机制摘要按实际配置显示，历史恢复保留原后端、设备与开关。cpu_driver 历史键保留，显示为「独立搜索驱动」。助手说明以 `markdown/AGENT_MODULE.md` 为准。
